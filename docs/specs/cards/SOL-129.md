# SOL-129 — Production observability

Owner, 2026-11-14: nobody is alerted when production breaks. Sentry project `soldi` (org `home-tdo`) created by the owner. Decided by the orchestrating session (D12); D38.

## Decisions

- **One Sentry project for both sides**, events tagged `side: server | web`. Server reads `SENTRY_DSN` at runtime; the web reads `NEXT_PUBLIC_SENTRY_DSN` at build time (Dockerfile `ARG`, Railway passes service variables as build args). No DSN = Sentry off (local, CI, tests). The DSN is not a secret but stays out of the repository.
- **What leaves the app:** the error, stack, route template, release (`CARGO_PKG_VERSION` / `web/package.json` version), environment. Never: money, e-mail, entry notes, request or response bodies, cookies, user id. `send_default_pii` false, UI click/input breadcrumbs dropped (their text can hold amounts), no performance tracing, no session replay.
- **Server:** the `sentry` crate (rustls, panic, backtrace, contexts, tracing). `tracing` events at `error` level become Sentry events through `sentry-tracing`; every 5xx `AppError` is logged at `error` with its source chain (verify, add if missing); panics are captured. `main.rs` holds the init (wiring only, excluded from coverage); any pure helper (options from env) lives in the library with a unit test.
- **Web:** `@sentry/react`, initialised once on the client in the existing root providers when the DSN is set. Reported: render errors (the app's `error.tsx` / `global-error.tsx` boundaries call `captureException`), unhandled errors and rejections (SDK default), and React Query query/mutation failures that are network errors or HTTP ≥ 500 — never 4xx (validation and 404 are the user's path, not a bug). The UI copy on errors does not change.
- **Web boot gap (accepted):** the SDK loads after first paint, when the browser is idle, to keep it out of the first load. Errors raised by the app code are held (at most 20) and sent once it loads; uncaught window errors and rejections raised before that are not captured. A blocked SDK (ad blocker, offline) drops the held errors silently. Session tracking (`BrowserSession`) is off; the environment is `production` on `getsoldi.app` and `preview` elsewhere.
- **CSP / headers:** if the server sends a Content-Security-Policy, `connect-src` allows the Sentry ingest host.
- **Uptime:** Sentry Uptime Monitor on `https://getsoldi.app/api/health`, created by the owner in Sentry → Monitors (no code).
- **Silent failures (SOL-120 class):** a GitHub Actions workflow `smoke.yml` runs one Playwright smoke spec against `https://getsoldi.app` after each release (on a pushed `v*` tag, waiting for `/api/health` to report that version) and on demand (`workflow_dispatch`) — owner, 2026-11-14: hourly is too much for a few users; add a schedule when usage grows, signed in as a dedicated account `smoke@getsoldi.app`-style (credentials in repository secrets `SMOKE_EMAIL`, `SMOKE_PASSWORD`). Flow: sign in, Mês, switch month back and forth, launch a Diário, see it, delete it. A failed run e-mails the owner (GitHub default). The account only ever holds its own throwaway entries.

## Acceptance

- Server: without `SENTRY_DSN` boots and behaves as today; with it, a forced 5xx and a panic reach Sentry tagged `side: server` with the release; no body or PII in the event.
- Web: without the DSN nothing loads from Sentry; with it, a thrown render error and a 500 from the API reach Sentry tagged `side: web`; a 422 does not.
- Smoke: `smoke.yml` passes against production; a broken month switcher would fail it.
- Gate unchanged: fmt, clippy, tests, sqlx check, typecheck, lint, coverage > 90%, build, e2e.
