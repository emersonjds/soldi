# SOL-161 — Switch a conta between fixa and parcelada, both ways

Owner, 2026-11-23. A Conta is a **conta fixa** (every month, no end) or a **conta parcelada** (N months: `installments` + `last_month`). The person switches an existing conta either way and it stays in Contas a pagar. Builds on D35 (Parar/Retomar, the plan), D44 and D45.

## 1. Current code

- `bills::service::update` merges `installments: patch.installments.or(current.installments)`. `UpdateBill.installments`/`last_month` are `Option<_>`, so `null` and absent both mean "keep": **parcelada → fixa is impossible**.
- Fixa → parcelada works: both fields together, `check_plan`, `last_paid` keeps the paid months. A plan never comes with `active` (422 `validation` on `active`).
- `Bill.active` is derived (`last_month IS NULL OR installments IS NOT NULL`): a parcelada is always active; a fixa with `last_month` is paused.
- D35 Retomar: `last_month = NULL`, `restart = ended` (`ended = last_month < this month`), which moves `active_since` to today (D17).
- `crate::nullable_field` already gives PATCH bodies an explicit `null` (`UpdateTransaction.card_id`, `UpdateCategory.parent_id`); `web/openapi.json` already types both fields `integer|null` / `string|null`.
- `BillForm` shows the Parcelado switch only when `!bill || (closing_day == null && installments == null)`. Its fixa path never sends `installments`.
- `TransactionSheet` shows the dead `recurringNote` "Já é uma conta fixa recorrente." on a payment (`recurring_bill_id`). Every host renders `billSheet={(props) => <EditBillSheet open {...props} />}`; ledger, bills-of-month and bill-list already read `useBills({ includeInactive: true })`.

## 2. Decisions

### 2.1 Contract: explicit `null` on both fields drops the plan
- `UpdateBill.installments: Option<Option<i16>>` and `last_month: Option<Option<NaiveDate>>`, each `#[serde(default, deserialize_with = "crate::nullable_field")]`, `#[schema(value_type = Option<i16>, nullable, minimum = 2, maximum = 60)]` / `#[schema(value_type = Option<chrono::NaiveDate>, nullable)]` (same attributes as `UpdateTransaction.card_id`).
- Absent = keep; both values = set (unchanged rules); both `null` = drop the plan. Any mix answers 422 `validation` on `last_month`, "send installments and last_month together" (today's message).
- `bills::domain::plan_patch(installments, last_month) -> Result<PlanPatch, AppError>` with `#[derive(Debug, PartialEq, Eq)] pub enum PlanPatch { Keep, Drop, Set { installments: i16, last_month: NaiveDate } }`; pure, unit-tested in `domain.rs`.
- Backward compatible: no client sends `null` today (web submit omits the keys; grep finds no `installments: null` in `web/src` or `web/e2e`). OpenAPI types stay the same; only descriptions change.
- Rejected: a new bool `parcelado: false` (two ways to say one fact, a third flag beside `active`); `installments: 0` (breaks `minimum = 2`, magic value); a `DELETE /api/bills/{id}/plan` route (new endpoint for one field pair).

### 2.2 What Drop writes
`repo::update` is unchanged; `service::update` passes `installments: None`, `last_month: None`, `restart: ended`. Exactly D35's Retomar:

| Case | `last_month` | `active` | `active_since` | Effect |
| --- | --- | --- | --- | --- |
| Running parcelada (end after this month) | NULL | true | kept | owes every month after the old end too |
| Last parcela this month | NULL | true | kept | next month owes; this month as before |
| Ended before this month | NULL | true | today | owes from today on (D17); `check_bill_kind` runs, as in Retomar |
| Months paid ahead | NULL | true | kept (ahead implies not ended) | payments stay; those months read paid |

Payments are never touched. Unpaid earlier parcelas of a running one still carry (D17). Rejected: no restart on an ended one (every month from the end to today reappears as `Venceu em …`); `active_since` = parcela 1's month (an extra rule for a round trip fixa → parcelada → fixa, which then owes the fixa's own months again, accepted).

### 2.3 Refusals (web text never from the server)
| Request | Answer | Web text |
| --- | --- | --- |
| Drop on a bill without `installments` (fixa, paused fixa, card) | 422 `validation`, field `installments`, "only a parcelado bill drops its parcelas" | never sent; fallback "Não foi possível salvar a conta." |
| Drop or Set with `active` | 422 `validation` on `active` (existing check, `current.installments.is_some() \|\| plan != Keep`) | form hides Ativa (§2.5); fallback |
| Mixed null/value | 422 `validation` on `last_month` | fallback |
| `closing_day` on a non-card | existing 422 on `closing_day` | fallback |
| Ended + archived category, none picked | 422 `validation` on `category_id` (Retomar's) | fallback |
| Another user's bill | 404 | fallback |

No new problem type, no `PROBLEMS` entry: the web never builds the refused bodies.

### 2.4 Fixa → parcelada on a paused fixa: confirmed, no change
`None if plan is Set && !current.active` → `(Some(last), ended)` with `check_bill_kind`: the paused fixa becomes an active parcelada; `active_since` moves to today only when its end was before this month. Covered by `d17_a_stopped_fixo_turned_parcelado_owes_from_today`; one test adds the not-ended case.

### 2.5 Web, `BillForm`
- Switch row condition becomes `!bill || bill.closing_day == null`: Parcelado shows on a parcelada, on, and can be turned off.
- Turned off on a parcelada (`bill?.installments != null && !draft.parcelado`), a helper under the label (like Valor varia's): **"Vira conta fixa: todo mês, sem fim. Os pagamentos feitos ficam como estão."**
- In that state the Ativa switch stays hidden (condition adds `bill.installments == null`), so `active` never rides with a Drop.
- `submit` fixa path: `onSave({ ...fields, amount, ...variable, ...(bill?.installments != null && { installments: null, last_month: null }) })`. Toggling back on restores the initial draft, so no plan keys go.
- `useSaveBill` toast: Drop → **"Agora é uma conta fixa"**; Set on a bill without `installments` → **"Agora é uma conta parcelada"**; anything else "Conta salva".
- `BillForm.onArchive` becomes optional; Excluir renders only when given. `EditBillSheet` passes it only when its own `onArchive` is set (today's sheet from a payment would close on a no-op Excluir).

### 2.6 Web, "Editar conta" on a payment
- `recurringNote` is replaced, same two places, by `PaidBill` (local component in `transaction-sheet.tsx`), rendered only when `transaction.recurring_bill_id` and `billSheet` exist. It calls `useBills({ includeInactive: true })` (fetches only for payments; usually cached by the host) and finds the bill by id.
  - `data` missing (loading or error): the button, `disabled`.
  - not found (archived, the list omits archived bills): muted text **"A conta deste pagamento foi excluída."**
  - found: `<Button type="button" variant="outline" className={kindButton}>` (`kindButton` hoisted to module scope) with `Pencil` icon `aria-hidden`, label **"Editar conta"**, or **"Editar cartão"** when `closing_day != null`.
- Click: `TransactionSheet` state `editingBill`; renders `billSheet?.({ bill: editingBill, onOpenChange: (open) => open || setEditingBill(undefined) })` next to the `converting` render. The entry sheet stays open beneath, like Transformar em conta.
- `billSheet` prop type: add `bill?: Bill`; `prefill` and `onCreate` become optional. Hosts unchanged.
- Rejected: a new `GET /api/bills/{id}` (the list already holds it); closing the entry sheet first (loses the entry on Cancelar).

## 4. D46 draft (for `docs/specs/decisions.md`)

## D46 — A conta switches between fixa and parcelada both ways (2026-11-23, owner + SOL-161; extends D35, D44, D45)

`PATCH /api/bills/{id}` with `installments: null` and `last_month: null` turns a parcelada into a conta fixa with no end; absent keys still keep the plan and values still set it. It writes what Retomar writes: `last_month` NULL, and `active_since` moves to today only when the plan ended before this month (D17). Payments are never touched. Only a parcelada drops a plan (422 `validation` on `installments`), never with `active`. Fixa → parcelada is unchanged, a paused fixa included. The web shows Parcelado on a parcelada and offers "Editar conta" on a payment entry. Trade-off: a fixa → parcelada → fixa round trip owes the fixa's own months again. Rejected: a `parcelado` bool, `installments: 0`, a plan endpoint. Detail: `docs/specs/cards/SOL-161.md`.
