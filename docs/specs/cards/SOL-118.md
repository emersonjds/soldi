# SOL-118 — One repeat model for Lançar and Contas fixas: fixo sem fim, parcelado com início e fim

Owner report 2026-11-12 (verbatim gist): Salário registered as "repete todo dia 15 por 12x", wants "sempre, por tempo indeterminado", Dezembro must read `2/12`. Dívidas/parcelas must show their position in every following month. Fies (boleto, conta fixa) ends em dez/2026 and today shows neither parcela nor end. Inglês (conta fixa, no end) must be stoppable, then gone from future months. Cartão and boleto purchases must launch as "parcela k/N". Reference: Organizze/Mobills split Fixa (sem fim, pode parar) vs Parcelada (N parcelas, pode começar na k).

Current model verified against the graph: `CreateTransaction.repeat_months` (2..60, D14) + `repeat_every` (D32) already give a bounded series with `k/N` read at request time (`web/src/widgets/ledger/ledger.tsx:138`); `installments` (D16) already splits a total k/N on a card or any Saída/Diário entry, cents remainder on the last; `recurring_bills` (D28) is the open-ended Saída-only entity with an `active` pause (`web/src/features/edit-bill/edit-bill-sheet.tsx:290-308`, copy "Ativa" / "Pausada, fica fora do mês e do projetado.") and no end date, no position, no start-at-k. Income can never be a bill (D14). So today: Salário already works as the owner describes for a *bounded* series — the gap is no "sem fim" mode anywhere, and bills have no end or position.

## Panel outcome

### 1. One mental model; where Salário fixo lives

- **product:** three options everywhere money repeats: `Não repete` / `Parcelado` / `Fixo`. One word, one place, no separate vocabulary for Lançar vs Contas fixas.
- **finance:** `Fixo` for income cannot become a recurring_bill (D14 stands: bills are Saída-only). It has to stay a transaction series that never runs out of rows.
- **ux:** replace the two existing switches ("Repetir lançamento (Série)" + "Parcelar compra") with one segmented control, same spot, same icons (`Repeat`, `Calculator`). `Fixo` reuses the `InfinityIcon` already in the series eyebrow.
- **architect:** a truly infinite series breaks D8/D14 (no unbounded rows ahead). `Fixo` is a series that auto-extends: when a month view reaches within D16's 12-month horizon of the series' last member, the service grows it by D19's existing mechanism (same code path as a user resize), so real rows always exist 12 months out and never fewer. One boolean, `series_indeterminate`, replaces the stored cap; `repeat_months` stops applying once it is set. Needs its own architecture card — this brief decides the surface, not the column.

**Winner:** one `Não repete / Parcelado / Fixo` control at every kind in Lançar. `Fixo` on Saída still offers "Criar como Conta Fixa" (unchanged); on Entrada or Diário it is an auto-extending series. Contas fixas keeps its own form (Saída only) but gains the same three words so Fies and Inglês read the same as a Lançar fixo.

### 2. A conta fixa with an end (Fies)

- **product:** registering Fies must say "termina em dez/2026" or "6 parcelas, já pago 2" up front — he should not have to count months by hand.
- **finance:** the due-day/Pago-Pagar machinery (D17, D28) already does the hard part; an ending bill is the same bill with a stop built in, not a new entity.
- **ux:** `Contas fixas` form gains a `Parcelado` switch beside `Cartão de crédito` (mutually exclusive): `Quantas parcelas` (2–60) and `Já pagas` (0 by default, seeds the start when registering a debt already underway elsewhere).
- **architect:** `recurring_bills` gains `installments: Option<i16>` (total) and `paid_before: Option<i16>` (seed). Position is `paid_before + months elapsed since active_since`, counted at read time like D17 already counts months, never stored. Reaching `installments` auto-sets `active = false` after that month's payment — the pause mechanic already there, no new state.

**Winner:** `installments` + `paid_before` on `recurring_bills`, read-time position, auto-pause at the last parcela. Needs an architecture card (new columns, `months/domain.rs` change).

### 3. Parar (Inglês)

- **product:** stopping must be one tap, no dialog — he already knows what it does.
- **finance:** past and paid months never move (D17); only future unpaid months disappear.
- **ux:** no new control — the existing `Ativa` switch in `edit-bill-sheet.tsx` *is* Parar. Keep its copy and placement; add nothing.
- **architect:** `active: false` already excludes a bill from every month from today on; already reversible.

**Winner:** reuse `Ativa` as-is. Undo over confirm: flipping it back on is the undo, no confirmation dialog either way.

### 4. Card/boleto parcela k/N

- **product:** a card purchase or a boleto split must read "parcela 1/10" from the first save.
- **finance:** `installments` (D16) already does this, cents remainder on the last, each member in its own fatura (D28).
- **ux:** reuse the ledger chip verbatim (`↻ Diário · 1/10`); the only gap is starting at a parcela already paid elsewhere.
- **architect:** `CreateTransaction` gains `starts_at: Option<i16>` (default 1) for both `installments` and `repeat_months`; the first `starts_at - 1` members are never written, `TransactionSeries.position`/`.total` read as if they existed. Needs an architecture card.

**Winner:** same installment series and same chip; add `starts_at` so a mid-stream debt can begin at its real parcela.

### 5. Open-ended fixo's position chip

- **product:** no denominator to read when there is none.
- **ux:** a static `Todo mês` chip replaces `k/N` wherever a series shows position (ledger row, Lançar eyebrow): `↻ Entrada · Todo mês`, eyebrow `Lançamento fixo, todo mês`.
- **finance:** forecast and Mês count it exactly like any other committed row (D16) because real rows exist up to the 12-month horizon (§1's auto-extend); no averaging, no guess.

**Winner:** `Todo mês` chip, `InfinityIcon`, same horizon rule as every other forecast row.

### 6. Owner's existing data (12x Salário, imported entries)

- **product:** no migration screen, no prompt.
- **architect:** rewriting one user's rows for one card is scope creep; D12's autonomous-delivery cost rule says no one-off script.
- **ux:** his 12x series keeps reading `1/12`…`12/12` until he opens it and turns it into `Fixo` himself (a new choice inside §1's control on an existing series, same place D19 already resizes one).

**Winner:** none. No background rewrite; converting is a user action on the existing entry, not a migration.

## States and acceptance criteria

- **Empty** (no bill, no series): Lançar shows `Não repete` selected; no parcela/fixo chip anywhere. (D25: a card with nothing to show renders nothing.)
- **First parcela** (`k=1`): row reads `Nome · 1/N`; no "última parcela" tag.
- **Last parcela** (`k=N`): row reads `Nome · última parcela` instead of `N/N`; paying it auto-sets `active=false` (bills) and the series stops growing (parcelado).
- **Stopped**: `Ativa` off; the bill is absent from today's month onward; past paid months in Lançamentos keep their rows and amounts untouched.
- **Resumed**: `Ativa` back on; `active_since` moves to today (D17, unchanged), so it never backfills months it could not see; position/parcela count (when `installments` is set) keeps counting from the real elapsed months, not from zero.
- **Paid** (mid-series or bounded bill): `Pago` badge/pill (unchanged `bill-status.tsx`); amount struck through on desktop.
- **Overdue**: `Vencido` pill, red tint row (unchanged `bills-of-month.tsx`); a carried parcela still reads its position, e.g. `Fies · 4/6 · venceu em nov`.
- **Fixo sem fim near its horizon**: at 12 months out from today, the series already has a real row waiting (auto-extend, §1); the chip never shows a denominator at any point.
- **375px**: `Não repete / Parcelado / Fixo` segmented control fits one row at 375px (3 equal chips, same `h-11` row used today for `Tipo`); `Quantas parcelas` / `Começa na parcela` stack to one column; the Contas fixas row's parcela tag wraps under the name before truncating it, never pushes the amount off-screen (same pattern as `BillsOfMonth`'s `Caption`, mobile line already handles wrap + truncate).

## Needs an architecture card (flagged here, decided elsewhere)

- `transactions`: `series_indeterminate` (or equivalent) replacing a fixed `repeat_months` cap; auto-extend job/trigger reusing D19's grow-at-end code path (§1).
- `recurring_bills`: `installments`, `paid_before` columns; position read like D17 counts months (§2).
- `CreateTransaction`/series: `starts_at` for `installments` and `repeat_months` (§4).

These three are data-model changes (D14/D16/D19 extensions) and belong to an `architect`-led card per the project's own rule ("architect only when the model or the contract changes"); this brief fixes the words, the states and the owner's trade-offs so that card has no open UX question left.

## Technical design (architect, 2026-11-12)

Decided here, not in a separate card. Replaces the `architect` votes in §1–§6 and the list above. Panel words, states and copy stand unless a line says **Changed**. Owner rule (2026-11-12, binding): Parar on a conta fixa, a Fixo series or a subscription removes the amount from the **following** months only; every past month, paid entry and Para onde vai history stays as it was. Reaching the last parcela behaves the same. Decisions: D35 (bills), D36 (series). Plan: `docs/specs/plans/SOL-118.md`.

### What the code does today (checked)

- `months::repo::bills` loads `WHERE (b.active AND b.archived_at IS NULL) OR b.closing_day IS NOT NULL`. With `active = false` the bill leaves **every** month view, past ones included: its paid row vanishes from Contas a pagar in the months it was paid (`tests/months.rs::rule_10_paused_and_archived_bills_leave_the_month_but_keep_their_entries` asserts this). `bills::service::pay` also 404s on a paused bill, so a carried month (D17) can no longer be paid. Brief §3 "Parar = `Ativa` as-is" and §2 "auto `active = false` at the last parcela" break the owner rule. **Rejected.**
- Resuming moves `active_since` to today (`bills::repo::update`). A position counted from `active_since` (§2's `paid_before + months since active_since`) restarts after a resume. **Rejected:** the position hangs on a stored end month.
- A series position is the rank by `(date, id)` over written rows (`transactions::repo::list` lateral). Parcelas never written need a stored offset.
- D19 growth (`transactions::domain::growth_dates`, `repo::series_end`, `repo::insert_copies`, `repo::lock_series`) already appends members after a series' last one, per step. Open series reuse it untouched.

### Model

**Bills end at a month (D35).**

- `recurring_bills.last_month date NULL`: first day of the last month the bill owes. Null: no end.
- `recurring_bills.installments smallint NULL` (2..60): a parcelado bill. Month `m` holds parcela `k = installments − months(m → last_month)`; the bill shows in `m` only when `1 ≤ k ≤ installments`.
- `recurring_bills.active` is dropped. `Bill.active` stays in JSON, derived `last_month IS NULL OR installments IS NOT NULL`: false means Parado.
- **Parar** (`PATCH {active: false}`, Fixo only): `last_month = max(this month, latest month with a payment)`. This month stays owed; the next ones never are.
- **Retomar** (`PATCH {active: true}`): `last_month = NULL`; when `last_month` was before this month, `active_since = today` (D17: stopped months never come back).
- **Fies**: created with `installments` and `last_month`. The web turns `Já pagas` into `last_month` (rule below). No write at the last parcela: months after `last_month` are simply not owed.
- One gate: `months::domain::owed` adds `month ≤ last_month`. Month view, Contas a pagar, the D17 carry and the forecast all go through it. Queries unchanged, two more columns.

**Open series grow as you read (D36). Option (b) wins.**

- `transactions.series_open boolean NOT NULL DEFAULT false` on every member, like `series_every` (D32).
- `transactions.series_offset smallint NOT NULL DEFAULT 0`: parcelas paid before Soldi. Position = offset + rank, total = offset + count.
- `transactions::service::extend_open_series(pool, user, until)` runs before month view, forecast and ledger list read rows. For each open series whose last member is before `until`, it locks the series (`lock_series`), re-reads its end, and appends copies of the last member through `until` with `growth_dates`. `until = open_until(today, viewed_end)`: the later of `horizon_end(today)` (D16, 12 months) and the viewed month's end, capped at 60 months from today and at 2100. Usually 1 indexed query and 0 writes. Concurrent GETs serialize on the lock and the second writes nothing.
- Rejected, (a) a general recurring rule (bills for income and card spends, projected, materialized on confirm). Income would need D17 for receipts: an unconfirmed salary lands "today" as phantom money, or a tap every month, and the owner wants no typing. Faturas (D28/D30), Para onde vai, Meu ano (D31) and Economia do ano read real rows, so each would need a projection branch. It also reverses D14 "income is never a bill".
- Rejected, a scheduled job: there is no scheduler in the binary, and reads are deterministic in tests.
- (b) keeps this/following/all edits, D30b, reports and `day_sums` as they are. Cost: three GETs may write (bounded, idempotent), and rows exist up to 60 months ahead at most.
- `Fixo` on Saída stays "Criar como Conta Fixa" (D8): `open_ended` is refused on `bill` kind. Card spends wait for SOL-119.

### Migrations (forward-only, like 0020)

`crates/soldi-server/migrations/0026_bill_last_month.sql`

```sql
-- SOL-118 (D35): a bill owes up to `last_month` (a month's first day); null owes with no end.
-- `installments` makes it parcelado: month m holds parcela installments - months(m -> last_month).
-- Forward-only; the revert lives in docs/specs/cards/SOL-118.md.
ALTER TABLE recurring_bills
    ADD COLUMN last_month date CHECK (last_month = date_trunc('month', last_month)::date),
    ADD COLUMN installments smallint CHECK (installments BETWEEN 2 AND 60),
    ADD CONSTRAINT recurring_bills_installments_end CHECK (installments IS NULL OR last_month IS NOT NULL),
    ADD CONSTRAINT recurring_bills_card_no_end
        CHECK (closing_day IS NULL OR (last_month IS NULL AND installments IS NULL));

-- A paused bill owed nothing; it now ends at its last paid month, or before it started owing.
UPDATE recurring_bills b
SET last_month = GREATEST(
        (date_trunc('month', b.active_since) - interval '1 month')::date,
        (SELECT max(date_trunc('month', t.date))::date FROM transactions t
          WHERE t.user_id = b.user_id AND t.recurring_bill_id = b.id))
WHERE NOT b.active;

ALTER TABLE recurring_bills DROP COLUMN active;
```

`crates/soldi-server/migrations/0027_open_series.sql`

```sql
-- SOL-118 (D36): an open series keeps growing on read; `series_offset` counts parcelas paid
-- before the first written member. Both live on every member, like series_every (D32).
ALTER TABLE transactions
    ADD COLUMN series_open boolean NOT NULL DEFAULT false,
    ADD COLUMN series_offset smallint NOT NULL DEFAULT 0 CHECK (series_offset BETWEEN 0 AND 59),
    ADD CONSTRAINT transactions_series_open_ck CHECK (NOT series_open OR series_id IS NOT NULL),
    ADD CONSTRAINT transactions_series_offset_ck CHECK (series_offset = 0 OR series_id IS NOT NULL);

CREATE INDEX transactions_open_series_idx ON transactions (user_id, series_id, date)
    WHERE series_open;
```

Revert, if ever needed. A parcelado bill becomes endless, and an open series keeps the rows it already wrote:

```sql
DROP INDEX transactions_open_series_idx;
ALTER TABLE transactions DROP COLUMN series_open, DROP COLUMN series_offset;
ALTER TABLE recurring_bills ADD COLUMN active boolean NOT NULL DEFAULT true;
UPDATE recurring_bills SET active = false WHERE last_month IS NOT NULL AND installments IS NULL;
ALTER TABLE recurring_bills DROP COLUMN last_month, DROP COLUMN installments;
DELETE FROM _sqlx_migrations WHERE version IN (26, 27);
```

Migration edge: a paused bill with an unpaid month between two paid ones now carries that month (D17). The pause used to hide it. Correct under D17. The owner sees it once as `Venceu em <mês>`.

### Read rules

1. `owed(bill, month)` = D17 as today AND (`last_month` is null OR `month ≤ last_month`) AND (no `installments` OR `k ≥ 1`).
2. `month_view` lists a bill in month `m` when it has a payment in `m`, or when `m ≤ last_month` and (no `installments` or `1 ≤ k ≤ N`). A card is unchanged (D28).
3. `BillOfMonth.installment` = `k` of the row's own month (`due_date`'s), carried rows included.
4. Pay refuses a month after `last_month` (`bill-ended`). Months ≤ `last_month` stay payable, stopped or not, so a carried month is still payable.
5. `GET /api/bills` without `include_inactive` hides bills with `last_month` before this month. `include_inactive=true` lists everything unarchived.
6. Series position = `series_offset + rank`, total = `series_offset + count`, in the three lateral queries (`list`, `movements`, `find`).
7. `extend_open_series` before reading in `months::service::get` (until `open_until(today, month_end)`), `months::service::forecast` (until `open_until(today, horizon_end(today))`) and `transactions::service::list` (until `open_until(today, month_end)`). Reports read past months only and skip it (a year view of a month never read is a known edge).

### Web
