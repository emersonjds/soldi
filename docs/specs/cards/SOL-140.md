# SOL-140 — Categories as a list, inline, in Lançar

Owner request 2026-11-14. Goal: a first-time, low-literacy, mobile-only user reaches any group or
subcategory from Lançar in one sheet, creates a missing one on the spot, and never creates a credit
card by accident as a plain category.

## 1. Context (current code, reused not rebuilt)

- `web/src/entities/category/category-chips.tsx` (`CategoryChips`): pinned/ranked top-level row +
  `Sub:` pills, "Personalizar" (opens `PinSheet`), "Ver todas" (opens `CategorySelect`).
- `web/src/entities/category/category-select.tsx` (`CategorySelect`): the "Ver todas" sheet — cmdk
  search, flat list, parent-of-another-kind as a header only (D26), "Nova categoria" row.
- `web/src/widgets/category-list/category-list.tsx` (`CategoryList`, Ajustes › Categorias): the
  group-card-with-children-and-"Adicionar subcategoria" pattern — **this is the file-model** for the
  new list body.
- `web/src/entities/category/category-sheet.tsx` (`CategorySheet`/`CategoryForm`): create/edit form,
  already skips the color picker and inherits the parent's icon/color when `parentId` is set.
- Cards: `recurring_bills` row with `closing_day` (D28); `web/src/features/edit-bill/edit-bill-sheet.tsx`
  (`BillForm`) has the `card` toggle → name, "Fecha dia", "Dia do vencimento", and a required
  `category_id` picked from existing `bill` categories (hint "Ex.: Cartão › Porto"). No create-card
  entry point exists inside Lançar today; `cardField` there is a plain `NativeSelect` over
  `useCards()`, shown only when a card already exists.
- Duplicate name check (`categories/repo.rs::name_taken`) is scoped to **active categories of the
  same kind** only — misses another kind and archived ones. `GET /api/categories` returns active
  categories only, no archived, no cross-kind search. No unarchive endpoint exists (archive is
  reversible only inside the 5 s undo toast, per the `ponytail:` note in `category-list.tsx`).

## 2. Lançar category step — list replaces chips + two-tier modal

One sheet, one tier (ponytail: cut `CategorySelect`'s nested cmdk dialog instead of adding a third
screen). The pinned row stays as the fast path; the list is always visible under it, not hidden
behind "Ver todas".

**375 px, kind already chosen (Entrada/Conta/Diário segmented control above):**

1. Tappable field: `Categoria` label, chosen value as `{Grupo} › {Subcategoria}` (`categoryLabel`) or
   placeholder `Escolher categoria`, chevron. 44 px row. Tap opens the sheet (`ResponsiveSheet`,
   bottom sheet < 1024 px).
2. Sheet title `Categoria`. Search input (`Buscar categoria`, 16 px, `Search` icon) — filters both the
   pinned row and the list by `plain(name)`, same substring rule as `CategoryList`.
3. Pinned row (unchanged `CategoryChips` ranking, up to 8 circles) under a small heading `Mais usadas`
   + a `Personalizar` link (opens `PinSheet`, unchanged). Tap a circle: chosen, sheet closes.
4. Divider, then the list: one card per top-level group of this kind, or a header-only card for a
   group of another kind that holds a subcategory of this kind (D26), exactly `CategoryList`'s
   `topsOf`/`ofKind` filtering. Each card:
   - header row: icon, name, `+` icon button (44×44, `aria-label="Adicionar subcategoria em {grupo}"`)
     — opens inline create (§3), never navigates away.
   - child rows: icon dot (parent's color), name; tap selects and closes the sheet.
5. List footer row: `+` icon in a dashed circle + `Novo grupo` (44 px) — opens inline create for a
   new top-level group (§3).
6. Credit cards: the `Cartão` group's header `+` and footer behave like every other group's `+` for
   **sub**categories, but see §4 — a card is never created as a plain subcategory there.

**Empty** (first sign-up before the seeds exist — should not happen post D29, kept as a guard):
card "Nenhuma categoria ainda" + the same `Novo grupo` row, no dead end.
**Loading**: skeleton pinned row (`CategoryChips` already has one) + 3 skeleton group cards.
**Error** (categories fetch failed): `PageError` "Não foi possível carregar as categorias." + Tentar de novo, pinned row and list both hidden (reuse `CategoryList`'s pattern).
**Offline**: same as error; the create button inside the inline form is disabled with the existing
mutation-pending state, no special offline copy (no optimistic category create exists today either).
**No search hits**: `Nenhuma categoria encontrada.` (existing `CommandEmpty` copy), `Novo grupo` row
stays visible below it so the empty state teaches the next step.

## 3. Inline create — new group, new sub, mixed-kind pick

Reuses `CategorySheet`/`CategoryForm` verbatim, opened with `parentId` preset for a sub, or plain for
a new group; both already render inside the Lançar sheet's stacking context (same `ResponsiveSheet`
pattern used today for `PinSheet`/`CategorySelect`'s create hop).

- **New sub under a group**: form opens already in "Subcategoria" mode, parent locked to the tapped
  group (no "Vincular à Categoria Pai" picker — it is already decided). Icon/color: inherited from
  the parent, no picker shown (existing `needsColor = !parentId` behavior) — matches "no picker unless
  needed".
- **Mixed-kind group** (D26, e.g. `Família` holding Saúde-Fixa and Educação-Diária subs): when the
  tapped group's existing children span both `bill` and `daily`, or it has none yet and the group
  itself does not fix the kind, show the existing `Tipo de Fluxo` segmented control (`Diário`/`Fixa`)
  already in `CategoryForm`'s `creatingFlow` branch — pre-selected to the kind Lançar is currently in
  (Conta → Fixa, Diário → Diário), one tap to change it.
- **New group**: segmented `Categoria Pai`/`Subcategoria` defaults to `Categoria Pai`; name field;
  `Tipo de Fluxo` segmented (income is excluded here — Lançar never creates an income group from
  Conta/Diário, kind follows the current Lançar kind otherwise, changeable); color auto-picked
  (`freeColor`), icon default `circle-dashed`, both changeable via the existing swatches/`IconPicker`
  but neither is required to save.
- **Save**: `BrandButton` "Criar Categoria" (sub) / "Criar Categoria" (group) — existing copy, unchanged.
  On success the sheet closes back to the category list with the new one selected and the chip list
  re-ranked next time (unchanged `useCreateCategory` cache update).
- **Undo**: creation has no undo (nothing destructive); archive keeps its existing 5 s "Desfazer" toast
  in Ajustes, unchanged by this card.

### Duplicate-name copy (pt-BR, exact)

Checked against the **active, same-kind** list client-side before submit (data already loaded):
> `Já existe uma categoria com esse nome` — unchanged 409 copy, inline under the name field.

For another kind or archived (needs the API extension in §6 — flagged, not built by this card):
> `"{nome}" já existe em {Grupo} ({Fixa|Diário|Entrada}).`
> button: `Usar esta categoria` (selects the existing one, closes the create form, returns to the list
> with it chosen) instead of submitting a duplicate.

For an archived match (no unarchive endpoint yet — flagged):
> `"{nome}" já existe, mas está arquivada. Reative em Ajustes › Categorias para usá-la.`
No action button until the unarchive endpoint ships; this line only prevents a second, confusing copy
from being created.

## 4. Cards never come from "+"

A card is a `recurring_bills` row (D28), not a category. The `Cartão` group's `+` opens the **same**
inline sub-create form as any other group, ***except*** the group flagged as the card group (see
flag below) swaps it for `Novo cartão`: `BillForm`'s card branch (name, `Fecha dia`, `Dia do
vencimento`) with the toggle hidden and `card` fixed `true`, and `category_id` auto-set by the server
to a new subcategory of `Cartão` named after the card (no category picker shown to the user — one
less field than today's `BillForm`, which currently makes the user pick or pre-create that
subcategory by hand; this is the exact bug the owner hit).

**Diário on a card today**: `cardField` in `transaction-sheet.tsx` is a plain `NativeSelect` over
`useCards()`, `Nenhum` + existing cards, shown only once a card exists. This card adds a `+ Novo
cartão` option at the end of that select's list (or a `Plus` row below it on native-select-unfriendly
platforms — keep the `NativeSelect` for the `44 px`/`16 px` native picker UX already working) that
opens the same minimal card form; on save the new card is selected on the entry being drafted.

## 5. Ajustes › Categorias — unchanged scope

Stays the only place to **archive**, reorder (pins) and move kind (`Tipo de Fluxo`, D27) — this card
adds no delete/reorder affordance to Lançar, per the owner's "deleting/archiving stays in Ajustes."
`CategoryList`'s "Adicionar subcategoria"/"Nova Categoria" entry points are untouched; Lançar's new
list is the same data, same components, read in a picker context instead of a management context.

## 6. Flags for architect (not decided by this card)

- **Card-group flag**: need a boolean on `Category` analogous to the existing `is_savings` (e.g.
  `is_card_group`) so the web can swap `Cartão`'s `+` for `Novo cartão` without matching on the
  localized name `"Cartão"`. Migration + `soldi-types` + OpenAPI bump.
- **Broader duplicate search**: `GET /api/categories` needs an `include_archived` (or a dedicated
  `GET /api/categories/check-name?name=&kind=`) so the inline create can warn about another kind or
  an archived match before POST, not just the same-kind-active 409 it gets today.
- **Unarchive**: no endpoint clears `archived_at` outside the 5 s undo window. Needed to make "Usar
  esta categoria" actionable for an archived match; until then that path is copy-only (§3).
- **Auto category on card create**: today `BillForm` requires picking `category_id`; this card
  proposes the server creates (or reuses) a `Cartão › {nome}` subcategory automatically when
  `closing_day` is set and no `category_id` is given. Confirm this is a `bills::service::create`
  change, not a web-side two-step (create category, then create bill) — the two-step risks a bare
  orphan category if the second call fails.

## 7. Votes on open questions (one agent, roles taken in turn)

- **Keep the pinned/recent chip row?** Keep it (ux). Trade-off: one more row of UI, but it is the
  only thing that keeps the common case at one tap; cutting it would slow every return visit to save
  space used once.
- **List always visible vs. behind "Ver todas"?** Always visible (product). Trade-off: a taller
  sheet on first open, but zero hidden affordance — matches "empty states teach the next step" and
  the owner's literal ask.
- **Card creation inline category vs. server auto-creates it** (finance): server auto-creates.
  Trade-off: one more backend branch, but a user who only wants a card never sees a category step,
  and Cartão stays exactly the "empty, for cards" group D29 promised.
- **Mixed-kind picker default** (architect): default to Lançar's current kind, no memory across
  sessions. Trade-off: a user flipping kinds on the same group re-picks every time, but a stored
  default is one more field to migrate for a one-tap saving.

## 8. Acceptance criteria

- [ ] At 375 px, every tap target in the category sheet (pinned circle, group `+`, child row, `Novo
      grupo`) is ≥ 44 px; the search input and every text field inside the inline forms are ≥ 16 px.
- [ ] Opening the category field shows the pinned row and the full list in one sheet, no second modal.
- [ ] A group of another kind that holds a sub of the current kind renders as a header-only card
      (unselectable itself), its matching sub(s) listed under it — screen reader announces the group
      name once per `aria-label` on the card, not repeated per child.
- [ ] Tapping a group's `+` opens the sub-create form pre-linked to that group, no parent picker, no
      color picker (inherits the parent's).
- [ ] A mixed-kind group's sub-create form shows `Tipo de Fluxo` pre-set to the current Lançar kind.
- [ ] Tapping `Novo grupo` opens the group-create form with `Tipo de Fluxo` pre-set to the current
      Lançar kind (income excluded) and a color already assigned without the user touching the
      swatches.
- [ ] The `Cartão` group's `+` opens `Novo cartão` (name, Fecha dia, Dia do vencimento), never the
      generic subcategory form, and never asks the user to pick a category.
- [ ] Creating a card from Lançar's Diário card select and picking it immediately fills `cardField`
      with the new card, no extra tap to re-open the entry form.
- [ ] A duplicate active same-kind name shows `Já existe uma categoria com esse nome` inline, save
      blocked, focus stays on the name field.
- [ ] Deleting or archiving a category remains reachable only from Ajustes › Categorias; no delete
      affordance appears anywhere in the Lançar sheet.
- [ ] Offline or a failed categories fetch shows `Não foi possível carregar as categorias.` with
      `Tentar de novo`; the sheet never shows a blank list without that message.

## Fintech review

Checked against Mobills (category screen `+` next to a group opens inline sub-create; category
create itself is a `...` menu → name/color/icon, color/icon required there) and Organizze (category
create is a *trip to the Categorias screen*, not inline in the lançamento — exactly the friction this
card removes). Neither has a "pick or create a card mid-expense" flow; Nubank's "cartão adicional" is
a different feature (a linked physical card, KYC flow) and not a precedent for §4 — no reference app
auto-creates a bookkeeping subcategory for a card, so §4's server-side auto-create is Soldi's own
simplification, not a copy; keep it, it removes a field competitors still show.

**Votes on §7:**
- Pinned row: keep (agree, unanimous already). Mobills keeps a "recent" strip for the same reason.
- List always visible: keep (agree). Organizze's extra-screen pattern is the anti-example to cite in
  the card, not a tie-breaker to debate.
- Card auto-creates subcategory server-side: keep (agree). Trade-off already correctly named in the
  brief; the two-step web alternative is the actual regression risk (orphan category), not a style
  choice.
- Mixed-kind picker defaults to current kind, no memory: keep (agree). One more vote: Mobills doesn't
  have this kind-of-flow concept at all (category kind is implicit in Entrada/Despesa tabs), so there's
  no reference to copy — the brief's own "no stored default" reasoning stands on its own.

**Trip hazards for a first-time, low-literacy user:**
- "Tipo de Fluxo" (§3, mixed-kind and new-group forms) is the one surviving jargon term in a brief that
  otherwise avoids it. A first-time user doesn't know "fluxo" means "quando isso entra/sai da sua
  vida". Replace the segmented control's label with `Quando acontece` and the options stay
  `Diário`/`Fixa` (already plain) — no new code, just the label the acceptance checks should pin.
- "Categoria Pai"/"Subcategoria" segmented control (§3, new-group form) uses "Pai" — a term this
  project's own global rules ban ("sem categoria pai"). Replace with `Grupo` / `Dentro de um grupo`
  (or reframe as the two rows already implied by the list: "Criar um grupo novo" vs. "Criar dentro de
  um grupo" — the second should arguably not even appear here, since §3's sub-create is already
  entered from a specific group's `+`; keep the segmented control only for the rare "I opened `Novo
  grupo` but meant a sub" recovery case, not as a first choice every time).
- `aria-label="Adicionar subcategoria em {grupo}"` (checklist item 3) — fine for a screen reader, but
  the **visible** `+` icon button needs no label row duplicating "subcategoria" in-screen; confirm no
  visible caption repeats the jargon next to the icon.
- Duplicate-name copy for another kind (§3) — `"{nome}" já existe em {Grupo} ({Fixa|Diário|Entrada})`
  mixes a user-created name with three system words in parentheses; a low-literacy user reads the
  parenthetical as noise. Shorter: `"{nome}" já existe em {Grupo}, para outro tipo de gasto.` and drop
  the `(Fixa|Diário|Entrada)` enum entirely — the button `Usar esta categoria` already resolves the
  action without the user parsing the kind.
- §4's `Novo cartão` swap on the `Cartão` group's `+` is the single highest-risk silent behavior in the
  brief: the icon looks identical to every other group's `+` but opens a different form. No visible
  cue (icon, microcopy) distinguishes it before the tap — add a one-line acceptance check (below) so
  pixel/qa doesn't wave it through as "it's just a `+` like the others."

**Wording swap table (pt-BR, drop-in):**
- `Tipo de Fluxo` → `Quando acontece` (label only; `Diário`/`Fixa`/`Entrada` options unchanged).
- `Categoria Pai` / `Subcategoria` (segmented, new-group form) → `Grupo novo` / `Dentro de um grupo`.
- `"{nome}" já existe em {Grupo} ({Fixa|Diário|Entrada}).` → `"{nome}" já existe em {Grupo}, para
  outro tipo de gasto.`
- `Escolher categoria` placeholder — keep, already plain; no change.

**Investor-grade acceptance checks (add to §8):**
- [ ] Log a spend in a brand-new subcategory in ≤ 4 taps after typing the amount: amount → `Categoria`
      field → group `+` → type name → `Criar Categoria` (auto-selected, sheet closes) → save entry.
- [ ] No screen in this flow shows the words "categoria pai", "lançamento recorrente", or "tipo de
      fluxo" verbatim; `Quando acontece` replaces the last one.
- [ ] The `Cartão` group's `+` button is visually indistinguishable from any other group's `+` at rest,
      but a first-time tap never lands the user on a form with an unexplained blank `category_id` —
      i.e. `Novo cartão` never shows a category picker, confirmed by screenshot diff against a plain
      group's `+` form.
- [ ] Typing a name that exists in another kind shows `Usar esta categoria` within the same sheet, with
      zero navigation away from Lançar, and tapping it returns to the entry draft with the amount still
      intact (no re-type).
- [ ] A one-handed thumb reach at 375 px: the `+` on every visible group card and the `Novo grupo`
      footer row are both reachable without scrolling past the keyboard when the amount field still has
      focus (i.e. opening the category sheet doesn't require dismissing the keyboard first to see the
      list).
- [ ] Creating a card from the Diário `cardField`'s `+ Novo cartão` and completing the minimal form
      returns the user to the *same* draft entry with the new card pre-selected and the amount/kind

- [ ] Every string unique to this card (search placeholder, empty state, duplicate-name copy, `Novo
      cartão`, `Novo grupo`) is present in the pt-BR locale file with no English fallback key visible
      at runtime.

## Technical design (architect, 2026-11-14)

Binding inputs: the brief above, the Fintech wording swaps and its added acceptance checks. Decisions
below close the §6 flags; cross-cutting ones are D43 in `docs/specs/decisions.md`.

### Flag 1 — a card without a dead category: cards land in the card group

- **Winner:** a card's `category_id` is optional on create. Absent, the server puts the card in the
  account's **card group** (the `Cartão` top-level) inside the same `bills::service::create`
  transaction. No per-card subcategory is created.
- **Why not the brief's auto `Cartão › {nome}` sub:** every reader of a card's category was checked.
  Para onde vai and Meu ano leave fatura payments out (`reports/repo.rs`, `b.closing_day IS NULL`, D28/D31);
  Mês and Contas fixas read only the category's icon and color (`months/repo.rs::bills`,
  `bill-list.tsx`). A per-card sub adds an insert, a name-collision branch (a card named `Luz` would
  409 against the `Luz` conta) and a row that outlives an archived card, for a label no report shows.
  The group adds none of that. Trade-off: payments of cards made from Lançar read `Cartão` instead of
  `Cartão › Porto`; the bill name (`Fatura Porto`) still names the card. Existing cards keep their
  category. Finance's vote (no category step for the user) is met in full.
- **How the server and the web know the group:** `categories.is_card_group boolean NOT NULL DEFAULT
  false`, mirroring `is_savings`. Migration `0029_card_group.sql` backfills it on each user's active
  top-level `bill` named `Cartão` (case-insensitive) and adds a partial unique index: at most one
  active card group per user. The D29 seed sets it on `Cartão`. `Category` gains `is_card_group: bool`.
  The web never matches the localized name.
- **No group active** (archived, or an old account that renamed it): `categories::service::card_group`
  creates `Cartão` (`credit-card`, lowest free `bill` color by `pick_color`), or, when an active `bill`
  named `Cartão` already exists, adopts it (`ON CONFLICT … DO UPDATE SET is_card_group = true`).
  `palette-full` (422) when all 24 `bill` colors are taken.
- **Rules on the group:** it keeps its kind (`kind-locked`, like Economia): moved to Diário it could no
  longer hold a card and a second flagged row would break the index. Rename, recolor, archive and
  re-parent stay allowed; a re-parented group loses its `+` swap but keeps working for cards.
- **Contract:** `CreateBill.category_id` optional; absent on a conta fixa → 422 `category_id` "is
  required". Present on a card → today's rules (bill category, never Economia or a cofrinho).
  `Category.is_card_group` added. Both additive for existing clients.
- **BillForm (Ajustes › Contas fixas):** the card branch drops its `Categoria` field and the
  `Ex.: Cartão › Porto` hint (create and edit) — the bug the owner hit, fixed at its source.

### Flag 2 — duplicate names: client-side over the loaded list; no new endpoint, no unarchive

- **Same kind, active:** the server's 409 stays the source of truth (`categories_active_name_idx`,
  `lower(name)` per kind). `CategoryForm` shows `Já existe uma categoria com esse nome` under the name
  field, `aria-invalid`, focus back on the name. No client preflight (it would duplicate the index).
- **Other kind:** `GET /api/categories` already returns every active category of every kind; the
  form compares `name.trim().toLowerCase()` (the index's rule) against active categories of **the
  other outflow kind** (Diário ↔ Fixa; income has one kind). Match → non-blocking line
  `"{nome}" já existe em {Grupo}, para outro tipo de gasto.` (a top-level match drops ` em {Grupo}`)
  and button `Usar esta categoria`, rendered only when the caller passes `onUseExisting`. Tapping it
  chooses that category; Lançar switches its kind to the category's and keeps amount, date and note.
- **Archived:** dropped. No unarchive exists anywhere (the 5 s undo only delays the DELETE), so
  `Reative em Ajustes` would point at nothing; the index allows an archived name again, so a new
  category with that name is harmless. No `include_archived`, no `name-check`, no unarchive endpoint.
  Add them with a card that ships an "Arquivadas" list.
- **Normalization:** case-only, the index's `lower(name)`. Accent folding (`Saude` vs `Saúde`) is not
  a duplicate for the server, so the form does not call it one.

### Flag 3 — mixed-kind groups, icon and color from Lançar

- **Sub from a group's `+`:** parent locked whenever `parentId` is preset (Ajustes' `Adicionar
  subcategoria` too): no `Grupo novo / Dentro de um grupo` segmented, no parent picker, no color
  picker (inherits, D15). `Quando acontece` (`Diário`/`Fixa`) shows only when the group is outflow,
  not Economia, and its children are not all of Lançar's current kind (mixed or empty); pre-set to
  that kind. Single-kind groups (Alimentação) skip it: the 4-tap path stays 4 taps.
- **`Novo grupo`:** segmented `Grupo novo` (default) / `Dentro de um grupo`; `Quando acontece`
  offers `Diário`/`Fixa` on the outflow side and is hidden when Lançar is on Entrada (income has one
  kind). Color pre-picked client-side by the existing `freeColor` and sent; icon defaults
  server-side to `circle-dashed`. The server keeps validating `color-taken`/`palette-full`. No change.
- **No `+` on Economia** in the picker: a cofrinho has target/deadline fields and lives in Cofrinhos.
- **Wording (global, one component):** `Tipo de Fluxo` → `Quando acontece`; `Categoria Pai` /
  `Subcategoria` → `Grupo novo` / `Dentro de um grupo`; `Vincular à Categoria Pai` → `Escolher
  grupo`; `Subcategoria de` → `Grupo`; `Escolha a categoria pai.` → `Escolha o grupo.`; aria
  `Categoria Pai ou Subcategoria` → `Grupo novo ou dentro de um grupo`.

### Web shape (FSD)

- `entities/category/category-picker.tsx` (`CategoryPicker`): the field (`Categoria`, value via
  `categoryLabel`, placeholder `Escolher categoria`) and one `ResponsiveSheet` with search
  (`Buscar categoria`), the pinned row (`Mais usadas` + `Personalizar`), the group list
  (`topsOf`/`ofKind`, moved from `category-list.tsx` to `categories-query.ts`), `+` per group,
  `Novo grupo` footer, and `CategorySheet` for inline create. Props: `kind`, `chosen`, `onChoose`,
  `entries`, `error`, `onNewCard?` (the card group's `+` calls it instead of the sub form).
- `CategoryChips` shrinks to the pinned row + `Personalizar`; its `Sub:` pills and `Ver todas` go,
  and `category-select.tsx` is deleted (the list replaces it). `purchase-simulator.tsx` swaps to
  `CategoryPicker` too (same component, no second picker).
- `entities/bill/day-fields.tsx`: `ClosingDay` and the due-day chips moved out of
  `edit-bill-sheet.tsx` unchanged. `entities/bill/card-sheet.tsx` (`CardSheet`, title `Novo cartão`):
  `Nome do cartão`, `Fecha dia`, `Dia do vencimento`, `Criar cartão`; posts `{name, due_day,
  closing_day}`; error `Não foi possível criar o cartão.`. In entities so `transaction-sheet` (a
  feature) can open it without importing another feature.
- `transaction-sheet.tsx`: `CategoryPicker` replaces `CategoryChips`. `cardField` shows on every
  Diário entry (`Nenhum`, the cards, `+ Novo cartão`); picking `+ Novo cartão` opens `CardSheet`,
  keeps the previous value, and on save selects the new card. The card group's `+` (Conta list)
  opens the same `CardSheet`; on save Lançar switches to Diário with the new card selected and the
  picker open on the Diário list (the reason to make a card mid-Lançar is to spend on it). Amount,
  date and note survive both round trips. Trade-off: users with no card see one more row on Diário;
  it is the only door to a first card from Lançar, which §8 requires.
- No locale file exists in `web/`; every new string is a pt-BR literal in its component, asserted
  verbatim by the component tests (the Fintech "locale file" check maps to that).
