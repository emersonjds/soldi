# SOL-173 — One occurrence of a conta: review this month's amount or skip it

Owner, 2026-11-27: in Mês > Modo planilha, a Saída cell (24 Dec: Caixa Habitação R$ 1.045,26 conta fixa, Porto Black R$ 101,47 fatura) opens the day detail, but the amount of that month cannot be reviewed: "por mais que seja uma saída o valor pode ser diferente... e precisa ser revisado". "A planilha é viva, não estática."

Backend model (decided by the orchestrator, not in this brief): a per-month override of one occurrence of a conta fixa or parcelada, never a card: `amount` for that month, or `skipped`. Paid occurrences are already a lançamento and keep Editar / Excluir.

## UX brief

### 1. User goal

"Before this conta lands, I set what it really costs this month (or say it doesn't come this month), and Projetado tells the truth right away. I never touch the other months by accident."

### 2. What stays the same (owner already uses these; D50, D55, SOL-153, SOL-186)

- Contas a pagar: the round check pays in **one tap** (fixed amount) or opens Pagar (variable, card). The name opens Editar conta (whole series, 1 tap); a card's name opens its fatura. A paid fixa's amount opens its payment (Editar / Excluir); Não paguei undoes. None of these change.
- Contas a pagar: tapping an unpaid amount still opens the same sheet, same hero amount prefilled, same "Quando pagou?" chips, and paying with another amount still takes the same taps. The sheet only **gains** actions (§4); it is the existing `PayBillSheet` improved in place, not a new picker.
- Planilha: an empty cell opens Lançar; a cell that is exactly one lançamento opens Editar / Excluir; "Lançar neste dia" + Entrada / + Saída / + Diário stay. Paid contas in the day detail stay a lançamento (Editar / Excluir).
- Lista: lançamento rows keep opening Editar / Excluir.

### 5. Rows everywhere (Contas a pagar, Lista DueRow, Planilha day detail and cell)

- **Unpaid**: as today. Lista DueRow becomes one button (whole row, min 44 px) with a trailing `ChevronRight` (aria-hidden); aria-label "Abrir {conta} de {mês}". A card DueRow opens its fatura (`FaturaSheet`).
- **Adjusted**: amount shows the override; caption gains "valor ajustado" (same slot and style as "valor variável", text, never color alone). A variable conta with an override drops the `≈` and "valor variável" for that month and reads "valor ajustado"; it still pays manually (D44).
- **Skipped**: row stays in its place; name and amount struck through and muted; caption "pulada em dezembro" (parcelada: "Parcela 3/10 · pulada"). The amount counts nowhere: not in Saída cell, group total, Contas a pagar total and "x de y pagas" (y drops it), Projetado, Saldo, Próximos meses, Posso comprar, RedDayAlert. No round check on a skipped row (the 44 px slot stays empty for alignment); the amount button opens the sheet with "Voltar a cobrar".
- **Paid**: unchanged (check filled; fixa's amount → payment; Planilha item → Editar / Excluir).
- **Overdue (Venceu)**: unchanged look; the sheet allows Pagar, adjust, or Pular (skipping an overdue month removes it from the Venceu count).
- **Variable (≈)**: unchanged until adjusted.
- **Optimistic** (save in flight): row shows the new amount / skipped look at once; in the Planilha detail it is text (no chevron, no button) with caption "Salvando…", as pending items today.
- **Fixed amount, D55**: on the due day the auto-payment uses the override amount; a skipped month is never auto-paid and never turns Venceu.

Planilha day detail: every tappable item (lançamento, unpaid conta, skipped conta, fatura) shows a trailing `ChevronRight` inside its existing 44 px button; the Diário previsto and optimistic items stay plain text, no chevron. Fatura item ("Porto Black · fatura") opens `FaturaSheet` for that card and month. The Saída cell sum uses overrides and drops skipped months.

### 6. Feedback, undo, errors (fixed pt-BR text, never server text)

| Action | Success toast (5 s, action "Desfazer") | Desfazer restores | Error toast |
|---|---|---|---|
| Salvar valor de dezembro | "Valor de dezembro ajustado" | previous state (old override or none) | "Não foi possível ajustar o valor. Tente de novo." |
| Voltar ao valor normal | "Valor normal de volta" | the removed override | "Não foi possível voltar ao valor normal. Tente de novo." |
| Pular dezembro | "Dezembro pulado" | unskipped | "Não foi possível pular este mês. Tente de novo." |
| Voltar a cobrar | "{Conta} volta a cobrar em dezembro" | skipped again | "Não foi possível voltar a cobrar. Tente de novo." |
| Pagar | unchanged (today's flow) | unchanged | unchanged |

- Saving: the sheet closes on tap and the row updates optimistically (like Pagar today); buttons are disabled while a mutation for that conta is pending. On error the row rolls back and the error toast shows.
- Invalid amount (empty, zero, not a number): existing `HeroAmount` invalid state on submit; neither Pagar nor Salvar sends.
- Offline / network failure: same error toast, the row rolls back.
- Loading: the sheet reads the month view already on screen, no spinner. Month view still loading: existing skeleton, nothing tappable.
- Month before `active_since` or after `last_month`: no occurrence exists, so no row and no sheet. If the server refuses anyway: "Este mês não tem esta conta." and the row rolls back.
- Overflow: long conta names wrap in title and rows (no truncation); amounts up to R$ 99.999.999,99 fit the hero at 375 px with no horizontal scroll; "fevereiro" in button labels wraps to two lines rather than clipping.

### 7. Parcelada

Skipping a parcela does not extend the plan; other months keep their numbering ("Parcela 4/10" stays on January). Adjusting a parcela changes only that month.

## Technical spec

Decision: D56. Plan: `docs/specs/plans/SOL-173.md`.

### 1. Model — migration `0033_bill_months.sql`

```sql
-- SOL-173 (D56): one month of a conta fixa or parcelada set apart: its own amount, or skipped.
CREATE TABLE bill_months (
    user_id    uuid NOT NULL,
    bill_id    uuid NOT NULL,
    month      date NOT NULL CHECK (extract(day FROM month) = 1),
    amount     numeric(12, 2) CHECK (amount > 0),
    skipped    boolean NOT NULL DEFAULT false,
    updated_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (user_id, bill_id, month),
    FOREIGN KEY (user_id, bill_id) REFERENCES recurring_bills (user_id, id) ON DELETE CASCADE,
    CHECK (skipped OR amount IS NOT NULL)
);
```

- PK is `(user_id, bill_id, month)`, not `(bill_id, month)`: the readers load `WHERE user_id = $1 AND month BETWEEN …` and the FK cascade looks up `(user_id, bill_id)`; one index serves both, no second index.
- Account deletion cascades users → recurring_bills → bill_months. Bills are archived, never deleted; an archived bill's rows stay dormant.
- `recurring_bills` does not change. Forward-only, like 0030/0032.

### 2. Rules

| # | Rule | Where |
|---|---|---|
| R1 | A month's amount = its override `amount`, else the bill's `amount` (a card: its fatura). | `months::domain::amount_in` |
| R2 | A skipped month is not owed: no `lands_on`, never `overdue`, not carried (D17), not in `days[].projected_balance`, `projected_balance`, forecast, never auto-paid. It stays in `bills_of_month` with `skipped: true` and `amount` = R1. | `months::domain::owed` |
| R3 | A payment wins: a month with a payment shows the payment (`amount` = paid, `adjusted: false`, `skipped: false`); its override stays dormant and comes back after Não paguei. | `month_view` own rows |
| R4 | Writes need: the caller's unarchived bill (else 404); not a card (422 `card-month`); `first_of(active_since) <= month` and `runs_in(bill, month)` (422 `month-outside-bill`); PUT only: no payment in the month (409 `bill-already-paid`, the existing slug). | `bills::domain::check_occurrence`, `bills::service::set_month` |
| R5 | Body: `amount` > 0, at most 2 places, below 10^10 (`settings::domain::check_money`); `amount: null` needs `skipped: true` (422 `amount`). `skipped: true` with an amount keeps that amount under the skip, so Voltar a cobrar / Desfazer brings it back. | `bills::domain::check_month` |
| R6 | DELETE answers 204 whether or not the month had a row; 404 only when the bill is not the caller's unarchived bill; no paid check (cleans a dormant row). | `bills::service::restore_month` |
| R7 | `POST /pay` without `amount` books the month's override, then the bill's amount (the one-tap check of an adjusted fixa). | `bills::service::pay` |
| R8 | D55: auto-pay books `COALESCE(override, bill.amount)`; a skipped month is never paid (R2). A variable conta with an override stays manual (D44). The watermark never rewinds: DELETE / Voltar a cobrar after the due day leaves the month open (Venceu) until Pagar, as Não paguei. | `insert_auto_payments`, `auto_paid` |
| R9 | Parcelada: numbering comes from `last_month`/`installments`; a skip never moves `last_month`, so other months keep "Parcela n/N". | unchanged `installment_in` |
| R10 | Dormant rows (outside the run after a plan edit, under a payment, on an archived bill) are ignored by readers; nothing cleans them. | readers |
| R11 | Locking: PUT and DELETE take only the user's entry lock (`transactions::repo::lock_entries`) first, then read. D55's order is settings → entries → bill rows; this is a subset, never settings after entries. The FK insert takes `KEY SHARE` on the bill row, which never conflicts with auto-pay's or PATCH's no-key `UPDATE`. | `bills::service` |

### 3. API contract

- `PUT /api/bills/{id}/months/{month}` (`month` = `YYYY-MM`), body `SetBillMonth { amount: string | null (default null), skipped: bool }`, `deny_unknown_fields`. 204. 400 `id` not a UUID; 401; 404 R4; 409 `bill-already-paid`; 422 `validation` (`month`, `amount`), `card-month`, `month-outside-bill`.
- `DELETE /api/bills/{id}/months/{month}`: 204; 400; 401; 404; 422 `month`.
- `BillOfMonth` gains `adjusted: bool` (unpaid month with its own amount; `amount` is it) and `skipped: bool` (R2). Response only.
- `POST /api/bills/{id}/pay` doc: "`amount` defaults to the month's own amount (D56), then the bill's".
- `web/openapi.json` regenerated (`UPDATE_OPENAPI=1 SQLX_OFFLINE=true cargo test -p soldi-server --test openapi`), then `pnpm gen:api`.

### 5. D55 interplay

- Adjusted fixa, due today or earlier after the watermark: auto-paid at the override (R8). Before the due day: "a pagar" at the override in Projetado.
- Skipped fixa: never auto-paid, never Venceu; the watermark passes it.
- Adjusted variable: still manual (D44); Pagar prefills the override (row `amount`).
- One-tap check on an adjusted fixa: server books the override (R7); optimistic row already shows it.
- Skip then unskip after the due day: the month stays open (Venceu) until Pagar (R8). Accepted, as D55's Não paguei.
- PUT on a paid month: 409; the payment is a lançamento, edited with its sheet.

### 6. Web

- `useSetBillMonth` in `entities/bill/bill-queries.ts`: one mutation; `{ amount: null, skipped: false }` sends DELETE, anything else PUT. Optimistic `patchRow`: `amount` (new amount, else `normal`, else the row's), `adjusted`, `skipped`, and on skip `lands_on: null, overdue: false`. Rollback on error; `refresh` on settle. Unskip does not guess `lands_on`: totals land with the refetch.
- Undo is the same mutation with the previous state `monthStateOf(bill) = { amount: bill.adjusted ? bill.amount : null, skipped: bill.skipped }`.
- `PayBillSheet` reads the normal amount from `useBills({ includeInactive: true })` (cached; already loaded by Contas a pagar and the Planilha). Until it loads, the scope and "o normal é" lines hide.
- Pagar error becomes fixed "Não foi possível marcar como paga." in the sheet.
- Cut: the Planilha "Salvando…" caption. The day detail hands off (closes) when the sheet opens, so a pending save is never on screen there; on reopen the refetch has landed.
