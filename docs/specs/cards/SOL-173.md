# SOL-173 — One occurrence of a conta: review this month's amount or skip it

Owner, 2026-11-27: in Mês > Modo planilha, a Saída cell (24 Dec: Caixa Habitação R$ 1.045,26 conta fixa, Porto Black R$ 101,47 fatura) opens the day detail, but the amount of that month cannot be reviewed: "por mais que seja uma saída o valor pode ser diferente... e precisa ser revisado". "A planilha é viva, não estática."

Backend model (decided by the orchestrator, not in this brief): a per-month override of one occurrence of a conta fixa or parcelada, never a card: `amount` for that month, or `skipped`. Paid occurrences are already a lançamento and keep Editar / Excluir.

## UX brief

### 1. User goal

"Before this conta lands, I set what it really costs this month (or say it doesn't come this month), and Projetado tells the truth right away. I never touch the other months by accident."

### 2. What stays the same (owner already uses these; D50, D55, SOL-153, SOL-186)

- Contas a pagar: the round check pays in **one tap** (fixed amount) or opens Pagar (variable, card). The name opens Editar conta (whole series, 1 tap); a card's name opens its fatura. A paid fixa's amount opens its payment (Editar / Excluir); Não paguei undoes. None of these change.
- Contas a pagar: tapping an unpaid amount still opens the same sheet, same hero amount prefilled, same "Quando pagou?" chips, and paying with another amount still takes the same taps. The sheet only **gains** actions (§4); it is the existing `PayBillSheet` improved in place, not a new picker.
- Planilha: an empty cell opens Lançar; a cell that is exactly one lançamento opens Editar / Excluir; "Lançar neste dia" + Entrada / + Saída / + Diário stay. Paid contas in the day detail stay a lançamento (Editar / Excluir).
- Lista: lançamento rows keep opening Editar / Excluir.

### 3. Market research: "change only this month's amount of a recurring bill"

| App | Screen and steps | Taps (typing excluded) |
|---|---|---|
| Organizze (web/app) | Lançamentos → tap the lançamento → edit Valor → Salvar → dialog "Somente este" / "Este e os próximos" ([help](https://ajuda.organizze.com.br/hc/pt-br/articles/5882498323347-Web-Lan%C3%A7amentos-Editar-lan%C3%A7amentos)) | 3 |
| Mobills (app) | Transações → tap the despesa fixa → Editar → edit valor → Salvar → "Alterar somente esta" / "Esta e próximas" ([help](https://mobills.zendesk.com/hc/en-us/articles/360050084953-How-to-edit-a-recurring-or-a-repeated-expense)) | 4 |
| YNAB (app/web) | Account register → tap the scheduled transaction → edit amount → Save → "only this one" vs "all future"; Skip next / Enter now on the same item ([help](https://support.ynab.com/en_us/how-to-edit-and-delete-transactions-BJG4oS1s)) | 3 |
| Monarch | Recurring → edit the merchant's recurring amount (series only); no per-month override found ([help](https://help.monarch.com/hc/en-us/articles/4890751141908-Tracking-Recurring-Expenses-and-Bills)) | n/a |

Pattern taken: the edit happens **on the item itself**, and the scope ("só este") is explicit. Pattern rejected: the scope dialog after Salvar (one more tap, and a modal question). Soldi states the scope in the button label instead ("Salvar valor de dezembro") and keeps "Editar conta" as the series path.

Soldi today vs proposal (taps, typing excluded):

| Flow | Today | Proposal |
|---|---|---|
| Change only this month's amount, from Contas a pagar | impossible (Pagar books it now; Editar conta changes every month) | 2: amount → Salvar valor de dezembro |
| Same, from Planilha (cell with 2+ items, the owner's 24 Dec) | impossible (item opens Editar conta = whole series) | 3: cell → item → Salvar valor de dezembro |
| Same, Planilha cell holding one unpaid conta only | impossible | 2: cell → Salvar valor de dezembro |
| Same, from Lista | impossible (DueRow not tappable) | 2: row → Salvar valor de dezembro |
| Skip this month | impossible | 2: amount/row → Pular dezembro (+1 from a Planilha 2+ cell) |
| Pay, fixed amount, Contas a pagar | 1 (check) | 1 (unchanged) |
| Pay with another amount, Contas a pagar | 2 (amount → Confirmar) | 2 (amount → Pagar) |
| Editar conta (series), Contas a pagar | 1 (name) | 1 (unchanged) |
| Editar conta (series), Planilha day detail | 2 (cell → item) | 3 (cell → item → Editar conta) — the only flow that grows; see Votes |
| Open a fatura from Planilha | impossible (text) | 2 (cell → item) or 1 when the cell is only the fatura |

### 4. The occurrence sheet (existing `PayBillSheet`, extended)

Opened from: Contas a pagar unpaid amount (as today), Lista unpaid DueRow (new), Planilha day-detail unpaid conta item (was Editar conta), Planilha Saída cell that is exactly one unpaid conta (new, extends D50's one-item rule). Cards never get these actions: their sheet stays Pagar as today.

Layout at 375 px, top to bottom (ResponsiveSheet: bottom sheet on mobile, dialog at 1440 as today):

1. Title: `{Conta} · {mês}` — "Caixa Habitação · dezembro". Wraps, never truncates.
2. Description (one line, muted):
   - fixa: "Conta fixa · vence dia 24/12"
   - parcelada: "Parcela 3/10 · vence dia 24/12"
   - overdue: "Venceu dia 24/11" (in `text-expense` plus the word Venceu)
   - variable: "Valor variável · confira o boleto"
   - month ≠ today's month keeps today's line under it: "Conta de dezembro: a data do pagamento fica em dezembro."
3. Hero amount (existing `HeroAmount`, ≥ 16 px, `inputmode="decimal"`), prefilled with **this month's amount** (override if any, else the bill amount; variable shows its estimate). Accessible label "Valor de dezembro".
4. Scope line, shown only while the typed amount differs from the prefill: "Só dezembro muda. Os outros meses seguem R$ 1.045,26."
   When the month already has an override: "Valor ajustado · o normal é R$ 1.045,26" plus link "Voltar ao valor normal".
5. "Quando pagou?" date chips (existing, unchanged).
6. Footer:
   - Primary (BrandButton, full width): **"Pagar"** (was "Confirmar"; the title no longer says Pagar). Pays with the typed amount and date, as today.
   - Secondary (outline, full width, appears only while the amount differs from the prefill): **"Salvar valor de dezembro"**. Saves the override, does not pay, closes the sheet.
   - Tertiary row, two text buttons, each min 44 px tall, 8 px apart: **"Pular dezembro"** (left) and **"Editar conta"** (right, opens today's Editar conta for the whole series; disabled while bills load, as `openName` today).

Skipped month, same sheet:
- Title unchanged; description "Dezembro pulado: esta conta não cobra neste mês."
- No hero amount, no chips. Primary: **"Voltar a cobrar"**. Tertiary: "Editar conta".

No confirm dialogs anywhere: every action closes the sheet and offers Desfazer (§6).

### 5. Rows everywhere (Contas a pagar, Lista DueRow, Planilha day detail and cell)

- **Unpaid**: as today. Lista DueRow becomes one button (whole row, min 44 px) with a trailing `ChevronRight` (aria-hidden); aria-label "Abrir {conta} de {mês}". A card DueRow opens its fatura (`FaturaSheet`).
- **Adjusted**: amount shows the override; caption gains "valor ajustado" (same slot and style as "valor variável", text, never color alone). A variable conta with an override drops the `≈` and "valor variável" for that month and reads "valor ajustado"; it still pays manually (D44).
- **Skipped**: row stays in its place; name and amount struck through and muted; caption "pulada em dezembro" (parcelada: "Parcela 3/10 · pulada"). The amount counts nowhere: not in Saída cell, group total, Contas a pagar total and "x de y pagas" (y drops it), Projetado, Saldo, Próximos meses, Posso comprar, RedDayAlert. No round check on a skipped row (the 44 px slot stays empty for alignment); the amount button opens the sheet with "Voltar a cobrar".
- **Paid**: unchanged (check filled; fixa's amount → payment; Planilha item → Editar / Excluir).
- **Overdue (Venceu)**: unchanged look; the sheet allows Pagar, adjust, or Pular (skipping an overdue month removes it from the Venceu count).
- **Variable (≈)**: unchanged until adjusted.
- **Optimistic** (save in flight): row shows the new amount / skipped look at once; in the Planilha detail it is text (no chevron, no button) with caption "Salvando…", as pending items today.
- **Fixed amount, D55**: on the due day the auto-payment uses the override amount; a skipped month is never auto-paid and never turns Venceu.

Planilha day detail: every tappable item (lançamento, unpaid conta, skipped conta, fatura) shows a trailing `ChevronRight` inside its existing 44 px button; the Diário previsto and optimistic items stay plain text, no chevron. Fatura item ("Porto Black · fatura") opens `FaturaSheet` for that card and month. The Saída cell sum uses overrides and drops skipped months.

### 6. Feedback, undo, errors (fixed pt-BR text, never server text)

| Action | Success toast (5 s, action "Desfazer") | Desfazer restores | Error toast |
|---|---|---|---|
| Salvar valor de dezembro | "Valor de dezembro ajustado" | previous state (old override or none) | "Não foi possível ajustar o valor. Tente de novo." |
| Voltar ao valor normal | "Valor normal de volta" | the removed override | "Não foi possível voltar ao valor normal. Tente de novo." |
| Pular dezembro | "Dezembro pulado" | unskipped | "Não foi possível pular este mês. Tente de novo." |
| Voltar a cobrar | "{Conta} volta a cobrar em dezembro" | skipped again | "Não foi possível voltar a cobrar. Tente de novo." |
| Pagar | unchanged (today's flow) | unchanged | unchanged |

- Saving: the sheet closes on tap and the row updates optimistically (like Pagar today); buttons are disabled while a mutation for that conta is pending. On error the row rolls back and the error toast shows.
- Invalid amount (empty, zero, not a number): existing `HeroAmount` invalid state on submit; neither Pagar nor Salvar sends.
- Offline / network failure: same error toast, the row rolls back.
- Loading: the sheet reads the month view already on screen, no spinner. Month view still loading: existing skeleton, nothing tappable.
- Month before `active_since` or after `last_month`: no occurrence exists, so no row and no sheet. If the server refuses anyway: "Este mês não tem esta conta." and the row rolls back.
- Overflow: long conta names wrap in title and rows (no truncation); amounts up to R$ 99.999.999,99 fit the hero at 375 px with no horizontal scroll; "fevereiro" in button labels wraps to two lines rather than clipping.

### 7. Parcelada

Skipping a parcela does not extend the plan; other months keep their numbering ("Parcela 4/10" stays on January). Adjusting a parcela changes only that month.

### 9. Acceptance criteria (tester checks)

1. Contas a pagar, unpaid Caixa Habitação, check: pays in one tap, as before.
2. Contas a pagar, tap the amount: sheet "Caixa Habitação · dezembro", amount R$ 1.045,26, chips, buttons "Pagar", "Pular dezembro", "Editar conta"; no "Salvar valor de dezembro" until the amount changes.
3. Type 1.100,00: scope line "Só dezembro muda. Os outros meses seguem R$ 1.045,26." and "Salvar valor de dezembro" appear; tap it: sheet closes, row shows R$ 1.100,00 and "valor ajustado", Projetado drops by R$ 54,74, toast "Valor de dezembro ajustado" with Desfazer for 5 s; January still R$ 1.045,26.
4. Desfazer within 5 s: row back to R$ 1.045,26, no "valor ajustado", Projetado back.
5. Reopen an adjusted month: "Valor ajustado · o normal é R$ 1.045,26" and "Voltar ao valor normal" restore the normal amount with toast "Valor normal de volta".
6. "Pular dezembro": row struck through with "pulada em dezembro", no check, amount out of Saída cell, totals, "x de y pagas", Projetado; toast "Dezembro pulado" + Desfazer. Reopen: "Voltar a cobrar" brings it back.
7. Parcelada 3/10 skipped: January still "Parcela 4/10", plan end unchanged.
8. Fixed-amount conta adjusted to 1.100,00: on its due day it reads paid at R$ 1.100,00 (D55). Skipped: never paid, never Venceu.
9. Variable conta adjusted: no `≈`, reads "valor ajustado", check still opens Pagar prefilled with the adjusted amount.
10. Planilha 24 Dec Saída cell (two items): day detail; Caixa Habitação item has a chevron and opens the occurrence sheet; Porto Black fatura item has a chevron and opens its fatura; Diário previsto has no chevron.
11. Planilha cell whose only Saída is one unpaid conta: opens the occurrence sheet directly.
12. Lista unpaid DueRow: whole row tappable (44 px, chevron), opens the occurrence sheet; a card DueRow opens its fatura.
13. Paid conta in Planilha detail and Lista: opens Editar / Excluir, unchanged.
14. Server error on each action: the fixed toast from §6 shows, row rolls back, no server text.
15. Empty or zero amount: invalid state, nothing sent.
16. "Editar conta" opens the whole-series form, unchanged.
17. Widths: no clipping or horizontal scroll at 375, 1024, 1280, 1440 (`expectNoClipped`); every new target ≥ 44 px; hero input ≥ 16 px.
18. Skipped and adjusted states read without color (strike-through plus text caption).

### Votes (panel, one line each)

- Improve `PayBillSheet` in place instead of a new "<Conta> · <mês>" action sheet: same taps for Pagar, no picker the owner must relearn (SOL-140 lesson); cost: one sheet with 4 actions.
- "Salvar valor de dezembro" appears only after the amount changes (progressive disclosure): keeps Pagar the one primary; cost: the action is not visible before typing (the editable hero is the hint).
- Planilha unpaid item opens the occurrence sheet, not Editar conta: the owner's reported need; cost: series edit from Planilha goes 2 → 3 taps (still 1 from Contas a pagar).
- Variable + override still pays manually (D44 kept): no surprise booking; cost: one tap more than a fixed conta.
- Primary label "Confirmar" → "Pagar": title no longer says Pagar; cost: e2e/test strings change.
- Other defaults (skip keeps parcel numbering, chevrons, Lista row, Desfazer 5 s, no card override) adopted as given.
