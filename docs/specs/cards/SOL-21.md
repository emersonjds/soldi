# SOL-21 — Repetir lançamento por N meses

Panel: `product`, `ux`, `finance` voted; `architect` arbitrated (2026-11-05). Depends on SOL-4 (`due_date` clamp, `bills/domain.rs`), SOL-20 (cofrinho/resgate fields), D7 (Decimal), D8 (bills never pre-generate rows), D13 (opening_date floor).

## Why

Rent, Netflix, gym: same amount, same day, every month. One launch with "Repetir por N meses" writes N−1 extra transactions instead of N manual ones, grouped by `series_id` so edit/delete can hit the whole run.

## Rules (finance → unit tests in `transactions/domain.rs`)

| # | Rule | Worked example | Edge |
|---|------|-----------------|------|
| R1 | Date clamp: each copy clamps the **original day-of-month** against *that month's own length* (same fn as `bills::domain::due_date`), never against the previous copy's clamped day. | Original 2027-01-31, N=4 → 2027-01-31, **2027-02-28** (2027 not leap), **2027-03-31** (back to 31, re-clamped from day 31, not from Feb's 28), 2027-04-30. | Day 31 in Feb: clamps to 28 (2027) / 29 (2028, leap). Year boundary: original 2026-11-30, N=3 → 2026-11-30, 2026-12-30, 2027-01-30 (`series_id` spans two years untouched). |
| R2 | N = **total occurrences including the original** (Mobills/Organizze convention: "repetir 12x" = 12 entries on screen, not 13). Copies created = N−1. Floor 2 in the card (`2..60`) is exactly this: N=1 would mean "repeat the original into itself," a no-op, so the range excludes it. | N=12, original 2026-11-05 Netflix R$ 39,90 → 1 original + 11 copies, last one 2027-10-05. All 12 share one new `series_id`, amounts and amount identical, 12 rows. | N=2 is the minimum real repeat: original + exactly 1 copy. |
| R3 | Copies are realized entries of their own future month, same as a manually-typed future entry; they never touch the **current month's** ledger or `projected_balance` (D8: projection only subtracts unpaid bills of *this* month). Repeat is **disallowed** when the entry has `recurring_bill_id` set (it is a bill payment, SOL-4) — the bill already recurs on its own `due_day` every month via computed projection; pre-writing future "paid" copies would fight that and go stale the day the bill's amount or `active` changes. UI offers "Transformar em conta fixa" instead (R8). | Launch R$ 50,00 Daily "Uber" repeat ×6 in November → November's `days`/`projected_balance` unchanged; December through April each get one R$ 50,00 Daily row. Try to repeat a `POST /bills/{id}/pay` transaction → 422 `repeat-not-allowed-on-bill-payment`. | None — the check is just `recurring_bill_id.is_some()`. |
| R4 | A cofrinho **deposit** (`bill` kind, category is a cofrinho or `Economia` itself, `cofrinho_id` null per SOL-20) repeats like any other bill-kind entry — "guarde R$ 200/mês" is the common case. A **resgate** (`income`, `cofrinho_id` set) is **not** repeatable: `insufficient-cofrinho` is checked against the balance *at pay time* (SOL-20 R-balance); a future-dated resgate can't know a balance that depends on deposits not yet made. | Deposit R$ 200,00 → `Economia › Reserva`, repeat ×12 → 12 monthly deposits, cofrinho balance grows by 200 each month it posts. Repeat a resgate → 422 `repeat-not-allowed-on-cofrinho-withdrawal`. | Deposit to `Sem objetivo` (Economia with no child) repeats the same way. |
| R5 | Every copy's date is `original_date` plus whole months, so if the original ≥ `opening_date` (already enforced, D13), every copy is too — no extra check at creation. | Opening 2026-11-01, original 2026-11-15, N=24 → last copy 2028-10-15, all ≥ opening_date trivially. | None; this is a non-rule kept explicit so backend doesn't add a redundant guard. |
| R6 | Edit scope (arbitrated, replaces finance's detach draft): **"Só este"** edits one row and it **stays** in the series (badge and `total` stable). **"Este e os próximos"** writes this row's resulting `amount`, `kind`, `category_id` and `note` onto every member with `date >= this row's date` (before the edit); past members are never touched. **Date never propagates**: only the edited row moves. | Series of 12 "Internet" at R$ 99,90, edit member #5 (2027-03-05) amount → R$ 109,90 "Este e os próximos" → #5–12 become 109,90, #1–4 stay 99,90. | #7 had a "Só este" 120,00; editing #5 "Este e os próximos" overwrites it to 109,90 (the user chose the scope). Changing the day of the whole run = a follow-up card. |
| R7 | Copies carry the **exact** Decimal amount of the original, no split, no proration, no re-rounding — `check_money`'s half-even-at-2-decimals already ran once on the original; copies reuse that `Decimal` value as-is. Sum of N copies for any report is `Decimal` addition, never `amount * N` as float. | Original R$ 1.234,57 (already half-even from input), N=5 → every copy reads exactly R$ 1.234,57; Σ over 5 = R$ 6.172,85 computed via 5 `Decimal` adds. | None — this rule exists to forbid a shortcut (multiply-then-round) that would differ from summing the five stored rows when the sheet is audited line by line. |
| R8 | "Transformar em conta fixa" (only for a `bill`-kind entry outside any series, offered as the alternative to repeat, and mandatory instead of repeat when `recurring_bill_id` is set, R3): creates a `bills` row with `due_day` = day-of-month of **this entry's date** (already 1–31, passes `bills::domain::check`), `amount` = this entry's amount, same category. This entry becomes that bill's payment for its own month (`recurring_bill_id` set on it, SOL-4 rule 2 shape). No copies are written for other months — the new bill's own `due_date`/projection machinery (SOL-4, D8) covers them from here on. | Daily→Bill-kind entry "Aluguel" 2026-11-07, R$ 2.259,56, "Transformar em conta fixa" → new bill `due_day=7`, amount 2259.56; this transaction gains `recurring_bill_id`; December's month view now lists it unpaid via the normal bill projection, not a repeat copy. | Entry dated the 31st → bill `due_day=31`, clamps per R1/SOL-4 rule 6 in short months, same as any other bill. |

## Not duplicated here

Month/year ledger boundaries, due-day-31-in-February clamp (generic case), a bill paid with a different amount, income same day as a bill, zero-income month (`rate_pct = None`), negative opening balance: all already unit-tested in `months/domain.rs` and `bills/domain.rs` (SOL-4). SOL-21 only adds R1–R8 above; it does not re-assert the existing projection/tier math.

## Arbitration (winner · trade-off)

- **Materialize N rows at once** (product + finance) over lazy generation: keeps D8's "transactions are the only ledger" and the one `GROUP BY date` month query. Trade-off: up to 59 future rows to rewrite on a series edit; bounded by N ≤ 60.
- **Two scopes, `this` and `following`** (product) over a third "Toda a série" (ux): past members are reconciled months and stay untouched. The card's "editar/excluir a série toda" is covered by the first member, where the `following` option reads `Toda a série`. Trade-off: from a later member, earlier months need their own edit.
- **"Só este" keeps membership** (product, ux) over detaching (finance): badge and `3/12` never shift. Trade-off: a later `following` edit overwrites a one-off change (R6).
- **Presets `2x 3x 6x 12x Outro`** (ux) over a stepper (product): chips match `DateChips` and 44 px targets. Default `12x` when the switch turns on.
- **Convert to bill links the entry server-side**, in one DB transaction; no "pay + delete" dance on the web.

## Model

- Migration `0015_transaction_series.sql`: `ALTER TABLE transactions ADD COLUMN series_id uuid;` + `CREATE INDEX transactions_series_idx ON transactions (user_id, series_id, date) WHERE series_id IS NOT NULL;`. No `series` table: a series is the rows sharing an id.
- `transactions/domain.rs` (pure, R1–R7 tests): `check_repeat(months: i16) -> Result<i16, AppError>` (2..=60, field `repeat_months`); `repeat_dates(date: NaiveDate, months: i16) -> Vec<NaiveDate>` (the N−1 copy dates: `bills::domain::due_date(first_of_month(date) + k months, date.day())`, k = 1..N−1, `checked_add_months`); `check_repeatable(&Transaction) -> Result<(), AppError>` (R3/R4 422s, plus `already-repeated` when `series` is set).
- `soldi-types`: `Transaction.series: Option<TransactionSeries>`, `TransactionSeries { id: Uuid, position: i64, total: i64 }` (1-based, by date).
- Read side, same `Row` in `list`/`find`/`movements`, still one query each:
  `LEFT JOIN LATERAL (SELECT count(*) AS total, count(*) FILTER (WHERE s.date <= t.date) AS position FROM transactions s WHERE s.user_id = t.user_id AND s.series_id = t.series_id) s ON true` (index-only, ≤ 60 rows; `series_id` NULL → `None`). Rejected: stored position/total (stale after a `following` delete), a window over the month's rows (wrong total), a window view (cannot push `user_id`).
- `repo.rs`: `insert` gains `series_id: Option<Uuid>`; `insert_copies(conn, user_id, entry, series_id, dates: &[NaiveDate])` = one `INSERT … SELECT $1, d, $3, … FROM UNNEST($2::date[]) AS d` (sqlx 0.9 FAQ pattern); `update_following(conn, user_id, series_id, from: NaiveDate, entry)` sets `amount, kind, category_id, note` where `date > from`; `delete_following(conn, user_id, series_id, from)` where `date >= from`; `set_series(conn, user_id, id, series_id)`; `link_bill(conn, user_id, id, bill_id, category_id)`. Every statement filters `user_id`.

## API (`web/openapi.json` regenerated)

- `POST /api/transactions`: `CreateTransaction.repeat_months: Option<i16>` (`#[serde(default)]`). Given: one DB transaction (`pool.begin()`), original inserted with `series_id = Uuid::new_v4()`, copies via `insert_copies`; 201 returns the original with `series { position: 1, total: N }`. 422 `repeat_months` outside 2..60.
- `PATCH /api/transactions/{id}?scope=this|following` (default `this`; other value → 400). `UpdateTransaction.repeat_months: Option<i16>` turns a standalone entry into a series (it becomes #1, copies after it); on a member → 422 `already-repeated`; bill payment → 422 `repeat-not-allowed-on-bill-payment`; resgate → 422 `repeat-not-allowed-on-cofrinho-withdrawal`. `scope=following` on a member: this row updated as today, then `update_following` from its old date, same DB transaction; on a non-member it equals `this`. 200 returns the edited row.
- `DELETE /api/transactions/{id}?scope=this|following`: `following` on a member runs `delete_following` from its date; 204.
- `POST /api/bills?transaction_id={id}` (only server change for R8; `CreateBill` untouched, onboarding unaffected): one DB transaction inserts the bill, then links the entry (`recurring_bill_id`, `category_id` = the bill's). Entry missing / another user's → 404; not `bill` kind, already linked, a resgate or a series member → 422 `cannot-become-bill`. 201 returns the `Bill`.

## Screens (ux; copy final)

- **Lançar / Editar** (`features/add-transaction/transaction-sheet.tsx`), below `DateChips`: switch `Repetir`. On → chips `2x 3x 6x 12x Outro` (`12x` preselected); `Outro` → numeric input (16 px, 2..60), error `Escolha de 2 a 60 meses.` Helper `12× R$ 150,00 · até out 2027` (count × amount · month of the last copy). Day ≥ 29 adds caption `Em meses mais curtos, cai no último dia.`
- Hidden in Editar when the entry has `recurring_bill_id` (shows `Já é uma conta fixa recorrente.`) or `cofrinho_id` (nothing shown) or is a series member.
- Saída with `Repetir` off and outside a series: link `Prefere uma conta fixa, sem data pra acabar? Transformar em conta fixa` → `EditBillSheet` prefilled (name = note or category name, amount, due day = the date's day, category). Saving: Lançar first creates the entry, then `POST /api/bills?transaction_id=`; Editar only the second call. Toast `Conta fixa criada`. Second call failing in Lançar → `Lançado, mas a conta fixa não foi criada.`
- Editing a member: header line `Parte de uma série de 12`, radio `Só este` (default) / `Este e os próximos` (`Toda a série` on #1). Toasts `Lançamento atualizado` / `Série atualizada`.
- Ledger action sheet (`widgets/ledger/ledger.tsx`), `Excluir` on a member: same radio, then `Excluir` (destructive) / `Cancelar`. Toasts `Lançamento excluído` / `Série excluída`; series members get no `Desfazer` (undo would re-create the row outside the series).
- Row caption for a member: lucide `Repeat` 16 px + `Saída · 3/12` (`aria-label` `3 de 12`).
- Create toasts: `Lançado` without repeat, `12 lançamentos criados` with it.

## Acceptance

- Backend: R1–R8 unit tests in `transactions/domain.rs`; repo/handler tests for create ×N (one transaction: a forced failure leaves zero rows), `following` edit/delete never touching earlier members, `this` keeping `series_id`, the four 422 slugs, 404 on another user's entry/series/`transaction_id`, `series` position/total in `GET /api/transactions` after a `following` delete; month view unchanged for the original's month.
- Web: Vitest for sheet states (switch off/on, each preset, `Outro` invalid/valid, helper and caption, hidden cases, bill-linked line, convert link only for Saída), scope radio labels (#1 vs later), toasts, ledger badge; e2e: Lançar `12x` → `12 lançamentos criados`, next month shows `Saída · 2/12`; delete `Este e os próximos` from #3 leaves `1/2`, `2/2`.
- Screens at 375 and 1440, light and dark; coverage ≥ 90% both sides; gate green.
