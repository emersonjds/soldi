# SOL-103 Meu ano Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a `/meu-ano` screen showing the year's Entradas and Gastos, where the income went, the months with the most spending, the top spending and income groups, and card spending. It is fed by one new endpoint, `GET /api/reports/year?year=`.

**Architecture:** the work extends the `reports` slice and creates no new slice.

- Pure: `domain::counted_range` and `domain::year_report`.
- Repo: two `GROUP BY` queries, `repo::year_flows` (by month and card) and `repo::year_groups` (by top-level category), both scoped by `user_id`.
- Service: `service::year` reads the settings, then runs the two queries.
- Totals reuse `soldi_types::months::Totals`, so the web reuses `splitOf` and `SplitBar` unchanged.
- Web: a new widget `widgets/year-review`, a page `/meu-ano`, and navigation in `widgets/app-shell`.

**Tech Stack:** Rust (axum, sqlx, rust_decimal, chrono, utoipa), Next.js 16 static export, TanStack Query, openapi-fetch, Vitest.

**Spec:** `docs/specs/cards/SOL-103.md`. **Decisions:** D16, D25, D28, D30, D31.

**Branch:** `feat/SOL-103-meu-ano` from `developer`, worktree `../soldi-103`.

## Global Constraints

- **Money:** `rust_decimal::Decimal` in Rust, and a string in JSON. Web sums and bar widths use `cents()` from `shared/lib/tier.ts`. Never a float.
- **User scope:** every query filters by `user_id`. The integration test proves that another user's entries change nothing.
- **Layers:** `domain.rs` is pure, `repo.rs` is sqlx, `service.rs` takes `&CurrentUser`, `handler.rs` is JSON. No trait.
- **No N+1:** the year is exactly two `GROUP BY` queries plus `settings::repo::find`. No query per month, per card or per group.
- **After SQL or DTO changes:**
  - `scripts/sqlx-prepare.sh`;
  - `UPDATE_OPENAPI=1 SQLX_OFFLINE=true cargo test -p soldi-server --test openapi`;
  - then `pnpm gen:api` in `web/`.
- **Web:**
  - FSD: imports go down only;
  - 375 first, 44 px targets, light only;
  - pt-BR copy verbatim from the card spec;
  - D25: a card with no content returns `null`.
- **TDD per task:** write the task's tests together, run them once red, write the code, run them once green, and report both runs.
- **Agents:** one opus agent per task, about 30 tool calls each. Agents commit on green and never merge or push.
- **Gate before merge:**
  - `cargo fmt --all --check`;
  - `cargo clippy --workspace --all-targets -- -D warnings`;
  - `cargo test --workspace`;
  - `scripts/sqlx-prepare.sh --check`;

**Interfaces (produced, used by Task 2):**

```rust
/// One month and card of the year by purchase date (D31); `card_id`/`card_name` only on a card's spends.
pub struct YearFlow {
    pub month: NaiveDate,
    pub card_id: Option<Uuid>,
    pub card_name: Option<String>,
    pub income: Decimal,
    pub withdrawn: Decimal,
    pub deposited: Decimal,
    /// Saídas without deposits and fatura payments.
    pub bills: Decimal,
    pub daily: Decimal,
}

/// A top-level category's total in the year; `income` tells an income group from an outflow one.
pub struct YearGroupSum {
    pub category_id: Uuid,
    pub name: String,
    pub icon: String,
    pub color: String,
    pub income: bool,
    pub amount: Decimal,
}

/// `year_range` cut at the end of today's month.
pub fn counted_range(year: i32, opening: NaiveDate, today: NaiveDate) -> Option<(NaiveDate, NaiveDate)>;

pub fn year_report(
    year: i32,
    range: Option<(NaiveDate, NaiveDate)>,
    flows: Vec<YearFlow>,
    groups: Vec<YearGroupSum>,
) -> YearReport;
```

The rules are in the card spec, "Endpoint":

- `totals.bills` = Σ `bills` + Σ `deposited`;
- `totals.daily` = Σ `daily`;
- `outflow` = `bills` + `daily`;
- `performance` = `income` − `outflow`;
- `saved` = `deposited` − `withdrawn`;
- `spent` = Σ `bills` + Σ `daily`;
- `top_months`: ≤ 3 with `spent` > 0, `spent` desc, then oldest first;
- `spending` and `income`: ≤ 5 each, amount desc then name, `pct = percent(amount, base).unwrap_or_default()`;
- `cards`: summed over the months, amount desc then name;
- `card_pct = percent(card_spent, spent)`;
- `first_month` and `last_month` from `range`, as `%Y-%m`.

**Tests (written together, one red run):**

- `counted_range`:
  - a past year runs to Dec 31;
  - the current year runs to `month_end(today)`;
  - a year before the opening is `None`, and so is a year after today's;
  - an opening in June starts on the opening date.
- `year_report`:
  - folds card rows into their month (two flows of the same month, one with a card);
  - ties in `top_months` go to the older month, with at most 3 returned;
  - a month with only deposits is not in `top_months`;
  - spending and income are cut to 5 and sorted by amount, then name;
  - `pct` is half to even with one decimal (copy `percentages_round_half_to_even`);
  - `card_pct` is `None` when `spent` is 0;
  - the totals identity holds: `totals.outflow − totals.saved − totals.withdrawn == spent`;
  - `None` range → `first_month`/`last_month` null, zeros, empty lists.

**What a naive build gets wrong:**

- Adding `deposited` to `spent`: Economia is saving (D31).
- Leaving deposits out of `totals.bills`: `splitOf` subtracts `saved + withdrawn` from `bills`, so Contas fixas goes negative.
- Counting a month twice because it has a card row and a non-card row: aggregate by month before ranking.
- Using `f64` anywhere, including the sort keys.
- Ranking all groups but computing `pct` over only the top 5: the base is `spent` or `totals.income`.

**Acceptance:** `cargo test -p soldi-server reports::domain` is green, and the new types compile in `soldi-types`.

**SQL (shape; the agent fixes the column aliases sqlx needs):**

```sql
-- year_flows: one row per month and card
SELECT date_trunc('month', t.date::timestamp)::date AS "month!", t.card_id, card.name AS "card_name?",
       COALESCE(SUM(t.amount) FILTER (WHERE t.kind = 'income' AND t.cofrinho_id IS NULL), 0) AS "income!",
       COALESCE(SUM(t.amount) FILTER (WHERE t.kind <> 'bill' AND t.cofrinho_id IS NOT NULL), 0) AS "withdrawn!",
       COALESCE(SUM(t.amount) FILTER (WHERE t.kind = 'bill' AND (c.is_savings OR COALESCE(p.is_savings, false)
           OR t.cofrinho_id IS NOT NULL)), 0) AS "deposited!",
       COALESCE(SUM(t.amount) FILTER (WHERE t.kind = 'bill' AND NOT (c.is_savings OR COALESCE(p.is_savings, false))
           AND t.cofrinho_id IS NULL AND b.closing_day IS NULL), 0) AS "bills!",
       COALESCE(SUM(t.amount) FILTER (WHERE t.kind = 'daily' AND t.cofrinho_id IS NULL), 0) AS "daily!"
FROM transactions t
JOIN categories c ON c.user_id = t.user_id AND c.id = t.category_id
LEFT JOIN categories p ON p.user_id = c.user_id AND p.id = c.parent_id
LEFT JOIN recurring_bills b ON b.user_id = t.user_id AND b.id = t.recurring_bill_id
LEFT JOIN recurring_bills card ON card.user_id = t.user_id AND card.id = t.card_id
WHERE t.user_id = $1 AND t.date BETWEEN $2 AND $3
GROUP BY 1, t.card_id, card.name;

-- year_groups: one row per top-level category and income/outflow
SELECT COALESCE(p.id, c.id) AS "category_id!", COALESCE(p.name, c.name) AS "name!",
       COALESCE(p.icon, c.icon) AS "icon!", COALESCE(p.color, c.color) AS "color!",
       t.kind = 'income' AS "income!", SUM(t.amount) AS "amount!"
FROM transactions t
JOIN categories c ON c.user_id = t.user_id AND c.id = t.category_id
LEFT JOIN categories p ON p.user_id = c.user_id AND p.id = c.parent_id
LEFT JOIN recurring_bills b ON b.user_id = t.user_id AND b.id = t.recurring_bill_id
WHERE t.user_id = $1 AND t.date BETWEEN $2 AND $3
  AND t.cofrinho_id IS NULL AND b.closing_day IS NULL
  AND NOT (t.kind = 'bill' AND (c.is_savings OR COALESCE(p.is_savings, false)))
GROUP BY 1, 2, 3, 4, 5;
```

**What a naive build gets wrong:**

- Joining `recurring_bills` on `card_id` alone: the join needs `user_id`, because the FK is `(user_id, card_id)`.

- Forgetting `cofrinho_id IS NULL` on daily or bills in one query but not the other: the identity `spent = Σ outflow groups` breaks. Keep the filters mirrored.
- A query per month or per card: two queries, full stop.
- Using `year_range` instead of `counted_range`: later months of the current year would leak in.
