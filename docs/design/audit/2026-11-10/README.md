# SOL-61 visual audit — Dashboard redesign

Seeded account `audit-sol61@example.com` (Postgres `soldi_61`, server on `:8081`, Next export on `:3000`-free static build). Screenshots at `docs/design/audit/2026-11-10/screenshots/`, named `<screen>-<width>-<theme>.png`, 1440×900 and 375×812, light and dark, for Mês, Para onde vai, Economia (Cofrinhos), Próximos meses, Ajustes, the Lançar sheet and the edit sheet of a series member (the seeded 12x "Streaming" series). Compared against `docs/design/stitch/*.png` (the approved direction) and the owner's two Duo Finn references described in the task.

## Ranked findings

1. **Desktop reads as a phone list stretched wide — no dashboard grid.** `/mes` at 1440 is a single vertical scroll of 30+ ungrouped daily rows (`mes-1440-light.png`, ~3900px tall) where the approved `docs/design/stitch/mes-dashboard.png` keeps everything above one fold: a compact "Próximos Lançamentos" (3 rows + "Ver extrato"), not the full ledger. The right rail (Termômetro + Próximos meses) ends a third of the way down the page, leaving the rest of the 900px-tall viewport, and everything below it, empty while the left column keeps scrolling. This is the single biggest gap from "a dashboard that answers more at a glance" — fix: cap the inline ledger (e.g. last 5-7 days) behind a "Ver extrato" link, like the reference, and let a 3-column bento (hero, contas, termômetro + a chart card) fill the fold instead of a 2:1 stack.
2. **"Economia" shipped as a 2-card Cofrinhos list, not the approved savings screen.** The approved `docs/design/stitch/economia-anual.png` is a full year view: hero with "Total consolidado", "8,4% das entradas", a goal/meta-anual progress bar, a 12-row monthly table (entradas, guardado, % guardado, status note, action menu) and three highlight tiles (consistência, maior aporte, rendimento). The shipped `/economia` route (`economia-1440-light.png`, `economia-375-light.png`) only renders "Guardado" total + two cofrinho cards — no year table, no goal, no projection, and the nav item itself was renamed "Cofrinhos". Either this is an accepted scope cut for this epic (then `tokens.md` §Layout and the card's acceptance criteria need updating to match) or it is unbuilt scope that should block "redesign done".
3. **No dark theme exists anywhere.** `mes-1440-light.png`/`mes-1440-dark.png`, `ajustes-375-light.png`/`-dark.png` and `economia-375-light.png`/`-dark.png` are byte-identical (same SHA-1) even with `prefers-color-scheme: dark` and a forced `.dark` class — `web/src/app/layout.test.tsx` asserts this is deliberate ("ships no dark token block ... no theme-mode or color-scheme detection"). `docs/design/tokens.md` already documents full dark values (`background #0F1222`, `card #1A1E36`, etc.) and both owner references show a theme toggle. This is the largest unmet item against the audit brief itself, which asked for light/dark on every screen.
4. **Lançar is a floating modal on mobile, not a bottom sheet.** `lancar-sheet-375-light.png` shows the same centered dialog used at 1440, with a visible gap above and below it; its primary "Salvar" button sits outside the fold (`clientHeight` 746 vs `scrollHeight` 862, measured directly) — a user must scroll inside the dialog to find the save action. `docs/design/stitch/lancar-bottom-sheet-mobile.png` is flush to the screen's bottom edge, has a drag handle, a numeric keypad instead of a bare input, and "Salvar Lançamento" always visible. Fix: a real `Sheet`/bottom-drawer component on mobile, sized to the viewport, with the submit action pinned.
5. **Fixed bottom tab bar eats the last row of every scrollable mobile list.** `ajustes-375-light.png` cuts "Minha conta" half under the tab bar; `para-onde-vai-375-light.png`'s "Top 5" card and the "Educação" row are partly hidden the same way (confirmed by a manual mid-scroll screenshot, not a fullPage-stitch artifact). The scroll container needs `padding-bottom`/safe-area reserved for the fixed nav height everywhere it appears.
6. **No top bar on desktop at all.** The approved mock has a breadcrumb ("Visão Geral / Outubro 2024"), a search box and a bell top-right (`mes-dashboard.png`); the shipped desktop (`mes-1440-light.png`) has none of that — the month switcher is buried inside the dark hero card instead of a persistent header, and there is no search or export affordance anywhere.
7. **Mobile header lost the identity/notification row.** The approved `mes-mobile-home.png` opens with "Olá, Emerson" + "Plano Pro" + a bell with an unread badge above the month switcher; the shipped `mes-375-light.png` only has the "Soldi" wordmark and a small avatar circle — no greeting, no notifications entry point anywhere in the mobile shell.
8. **Hero number has no cents hierarchy.** `mes-375-light.png`'s "R$ 15.519,68" renders reais and centavos at identical weight/size; the design brief (and both Duo Finn references) calls for a visibly smaller, lighter cents suffix. Right now the full figure reads as one dense block instead of a value with a legible primary number.
9. **Series/installment date input breaks the app's own date convention.** `editar-serie-sheet-1440-light.png`'s native `<input type=date>` shows "11/05/2026" (mm/dd, i.e. Nov 5) while every other date in the product is dd/mm (`"Vence dia 05/11"` on the same screen, one card over). The unstyled native picker isn't locale-pinned to pt-BR, so it silently contradicts the rest of the UI on the exact kind of screen (money, dates) that most needs consistency.
10. **Mobile ledger has no rhythm or grouping delight.** `mes-375-light.png` stacks ~30 same-height icon rows back to back with only a thin date label between days; there's no card separation, no empty-state illustration anywhere seeded (cofrinhos empty state is plain text per `cofrinhos.spec.ts`), and nothing like the references' 3D wallet/calendar art. Low urgency next to 1-9, but it's what turns "functional" into "a pleasure to use".

## What Soldi already does better — keep it

- The thermometer never relies on color alone: every pill and the "Termômetro do Mês" strip pairs the dot/segment color with a text label (Crítico/Atenção/Apertado/Confortável/Folga) visible in every screenshot, including the "Próximos meses" chips (`abr 2027: Crítico, 26 dias no vermelho`) — stronger WCAG discipline than either Duo Finn reference, which leans on bar color and position alone.
- The running day-by-day balance inline in the ledger (`R$ 15.519,68 Folga` recomputed per row as entries are added/removed) is a feature neither reference shows; Duo Finn only totals monthly, Soldi shows the trajectory.
- The forward "Projetado" card plus the "Próximos meses" 6/12-month strip with per-month tier and red-day counts (`mes-1440-light.png`) goes further than the reference's single "Projeção de Fechamento" figure — it's a genuine multi-month forecast, not just this month's endpoint.
